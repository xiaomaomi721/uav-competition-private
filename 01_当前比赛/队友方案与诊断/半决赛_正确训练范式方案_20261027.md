# 半决赛正确训练范式方案（基于 CaSC 代码诊断）

> 日期：2026-10-27
> 性质：基于对队友 CaSC 训练代码（`h76_train.py` 845 行）的逐行诊断，重新设计「利用 test3 3594 张无标签图」的正确训练范式。
> 基线：H75+Bstar = 70.998665%；目标 72。

---

## 一、数据真相（先纠正三个根深蒂固的误解）

| 数据 | 数量 | 半决赛变化 |
|---|---:|---|
| source 训练集（有标签） | 5597 | **没变** |
| source 验证集（有标签） | 1399 | **没变** |
| test3 无标签测试图 | 3594 = 500+1300+1794 | **变多** |

**关键：官方有标签数据（train+val）从头到尾没变，变的是无标签测试图。** 所以「数据变多了」的正确含义是「可用的无标签目标域图变多了」，而不是「训练数据变多了」。这决定了训练范式必须为「无标签域适应」重设计，而不是简单地「加 epoch」。

---

## 二、队友 CaSC 的三个根本错误（代码读出的，非猜测）

### 错误 1：用 source1399 做模型选择（已证伪）

CaSC 代码里 `val_guard`/`val_proxy` 都是 source1399 切出来的（`split["guard_ids"]`/`proxy_ids`），训练中每 600 步用它评估、最终用它做放行门槛。

**但今天已证明 source1399 在 test3 上方向选反**：Zero 在 source 高 +2.91pp、test3 低 −3.02pp。**拿它做 guard/proxy 放行门槛，等于拿一个反相的尺子选模型。**

### 错误 2：步数与 epoch 混淆

CaSC 设 `max_effective_steps = 3594`，语义是「每个 target ID 覆盖一次」。但 source 采样是 `src_ds[source_consumed % 5597]`——**3594 步里 source 只消费了 3594 张，连一个 epoch（5597）都没跑完**。

后果：source GT（唯一可靠监督）在训练中被严重欠采样，而 target 伪标签（不可靠监督）被完整覆盖。**可靠信号没吃够，不可靠信号吃太饱。**

### 错误 3：伪标签可靠性判据 = 绝对置信度（test3 上失效）

CaSC 的 `build_pseudo` 用「单尺度置信度 ≥ 阈值（荒地 0.64）+ margin + 两视图一致」。但荒地 precision 在 source 上只有 48%，test3 无标签只会更差。

**用绝对置信度选伪标签，会大量把「自信的错误」当监督**（荒地 precision 48% 意味着选出来的荒地里一半是错的）。

## 三、正确的训练范式（核心设计）

### 3.1 起点：用 CTRL 续训 checkpoint，不是 H75

**依据**：CTRL（source-only 续训）已把荒地 IoU 46.14→53.60（TTA8 口径 +7.45pp），荒地 precision 从 48% 修复到 ~60%。这是「补表征」的确定性收益。域适应应该从这个更强的起点出发，而不是从欠收敛的 H75 出发。

- 起点 = `experiments/ctrl/checkpoints/stage1_complete.pt`

### 3.2 教师：用 CTRL 自身打 test3 伪标签（单教师，不用 H75）

**依据**：伪标签教师必须「比学生强或至少相当」。CTRL 荒地 precision 60% > H75 48%，用 CTRL 打伪标签，荒地的伪标签更准。用 H75 打伪标签反而会污染（H75 荒地 precision 更低）。

- 教师 = CTRL checkpoint 冻结，`eval()`+`no_grad()`

### 3.3 伪标签可靠性判据（核心创新点）：precision 优先，不是 recall 优先

**这是我前面两个失败验证后得到的真正 insight**：伪标签的目的不是「选全」（recall），而是「选准」（precision）。因为伪标签错了会 self-confirm 污染训练，而选少只是少覆盖几个像素（source GT 兜底）。

我前面多尺度验证的数据证明了这一点：
- 单尺度置信度 0.64：precision 0.862 / recall 0.764 / f1 0.810
- 三尺度 argmax 一致：precision **0.866** / recall 0.728 / f1 0.791

我之前用 f1 判它失败，**但 f1 是错的判据**。伪标签场景下 precision 0.866 > 0.862 才是关键——多尺度一致确实提高了 precision，只是牺牲了 recall。而 recall 低没关系，因为还有 source GT 兜底。

**正确判据**：
1. **三尺度 argmax 一致**（0.75×/1.0×/1.25× 都判同一类）——提高 precision
2. **+ 三尺度平均置信度 ≥ 类阈值**（弱类阈值更高，荒地/农田 0.7）——再提高 precision
3. **+ 弱类定向**（只对荒地/植被/农田做伪标签监督，其余靠 source GT 锁住）

**关键区别**：队友用「单尺度置信度」，我用「多尺度一致 + 平均置信度」，且明确目标是 **precision 最大化**，recall 低可接受。

### 3.4 步数 / epoch / 采样（纠正错误 2）

| 项 | 队友 CaSC | 正确设计 | 依据 |
|---|---|---|---|
| 步数 | 3594（target 覆盖数） | **5597**（source 一个完整 epoch） | source GT 是唯一可靠信号，必须吃满 |
| source 采样 | `%5597` 顺序，3594 步没跑完 | **5597 步无放回跑完一个 epoch** | 可靠信号优先 |
| target 采样 | 3594 ID 各覆盖一次 | 前 3594 步无放回覆盖全部，后 2003 步复采弱类多的图 | 弱类定向 |
| source:target | 1:1 每步各一张 | 每步 source 1 + target 1，但步数=5597 | target 复采而非 source 欠采样 |

### 3.5 验证集（纠正错误 1）——这是最难的部分，必须诚实

**source1399 降级为「崩坏检测器」，不是「模型选择器」**：

- 崩坏检测：source1399 mIoU 相对 CTRL 起点掉 > 2pp → 停止（说明灾难性遗忘）
- 不做：source1399 涨了 → 选它（因为 source1399 在 test3 上方向反）

**模型选择改用「固定步数 + 多 checkpoint 保留 + 线上分裁决」**：
- 固定训练 5597 步，在 2000/3500/5597 步各存一个 checkpoint
- 三个 checkpoint 都不在 source1399 上做选择
- **最终靠线上分裁决**（test3 无标签，这是唯一 ground truth）
- 代价：可能需要提交 2-3 个候选才能确定最优，但这是「验证集失效」下的必然代价

**辅助弱信号（不用于放行，只用于监控）**：
- test3 伪标签类别占比 vs source 真实占比的偏移——监控「分布对齐度」，偏移过大说明伪标签崩了

### 3.6 损失（单机制，不堆叠）

```
L = 1.0 * L_source_CE          # source GT 主导（防遗忘）
  + 0.1 * ramp(k) * L_target   # 弱类定向伪标签 CE（只荒地/植被/农田）
```

**明确移除**：context 一致性、scale 一致性、anchor（队友 CaSC 的另外三个模块）。**单机制，可归因**。

`ramp(k) = min(1, k/800)`，k 是有效步数。target 系数 0.1 远小于 source 1.0，保证伪标签只是「补充弱类」而非「主导」。

### 3.7 优化器 / 超参（续训范式，不是初训）

| 项 | 值 | 依据 |
|---|---|---|
| lr（stage2/3） | 1e-6 | 比 CaSC 的 3e-6 更低，因为起点是已续训过的 CTRL |
| lr（head） | 5e-7 | 同上 |
| weight decay | 0.01 | 沿用 |
| warmup | 100 步 | 沿用 |
| 调度 | poly power 0.9 | 沿用 |
| 可训练层 | stage2/stage3/decode_head，其余冻结 | 历史已验证防遗忘 |
| batch | 1 + 梯度累积 1 | 1024 大图显存限制 |
| AMP | 开启 | 沿用 |

## 四、与 CTRL 的关系（重要，避免混淆）

- **CTRL（source-only 续训）= 域适应的「起点」，不是「最终提交」**
- 本方案 = 在 CTRL 起点上，用 test3 3594 张做「弱类定向伪标签域适应」
- 预期收益链：CTRL 已 +1.59pp（收敛收益）→ 本方案再 +?（域适应收益，补那 9pp 表征域差的一部分）

**两者可以都提交**（如果额度允许）：
- 先提交 CTRL（确定性 +1.59pp，零伪标签风险）
- 再提交本方案的域适应结果（风险更高但可能补更多）

---

## 五、风险与止损

| 风险 | 止损 |
|---|---|
| 伪标签污染（即使 precision 优先，仍可能 self-confirm） | source1399 崩坏检测掉 >2pp 即停 |
| 灾难性遗忘 | source CE 系数 1.0 主导 + 冻结底层 + 极低 lr |
| 验证集失效导致选错 | 固定步数 + 多 checkpoint 保留，线上分裁决 |
| 弱类定向导致其他类退化 | 每步都跑 source1399 崩坏检测（掉 >2pp 停） |

---

## 六、诚实边界

1. **本方案不保证提分**。test3 无标签，伪标签域适应的收益无法在训练中验证，只能靠线上分。
2. **验证集失效是信息论限制**，不是我能力不足——无标签目标域下，「哪个 checkpoint 更好」只有线上分能回答。
3. **CTRL 是确定性收益（+1.59pp 已验证），本方案是高风险高回报**。建议先锁定 CTRL，再试本方案。

---

## 七、一句话总结

**队友 CaSC 错在三件事：用已证伪的 source1399 选模型、3594 步连 source 一个 epoch 都没跑完、用绝对置信度选伪标签。** 正确的范式是：从 CTRL 起点出发，用「多尺度一致 + 弱类定向」做 precision 优先的伪标签，跑满 source 一个 epoch（5597 步），source1399 只做崩坏检测不做选择，最终靠线上分裁决。
