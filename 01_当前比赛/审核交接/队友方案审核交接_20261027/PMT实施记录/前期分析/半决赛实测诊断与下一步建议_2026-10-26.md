# 半决赛实测诊断与下一步建议

日期：2026-10-26。目标仍为线上 72 分。本报告依据本轮实际服务器分析，修正此前“优先直接提交 M2F”的建议，不按剩余提交次数预排路线。

## 本轮实际做了什么

- 在新服务器物理 GPU1 上完成 H75 单视图推理：全部半决赛 3,594 张，以及固定随机种子抽取的 source train 256 张、source val 256 张，共 4,106 张。推理循环耗时 608.25 秒，PyTorch 峰值分配约 2,002 MiB；进程结束后 GPU1 回到 18 MiB、0%。未使用 GPU0。
- CPU 读取 1,399 张源域真值、H75 原始 logits 和 M2F 区域缓存，计算逐类互补性；复算区域教师实际 25% 软混合；核对历史“99.3% 精度”的定义。
- 提取图像外观统计、H75 最后一层特征、类别预测占比、偏置引起的翻转；完成固定抽样可视检查和候选图像对的 SIFT/RANSAC 几何验证。
- 对相关论文做机制核验，按项目实测判断是否值得采用，而不是直接把论文涨分当比赛涨分。

本轮没有训练、没有提交比赛、没有修改队友训练代码或权重。结果及脚本保存在本项目目录；服务器独立输出根目录为 `/data/uav/analysis_codex_20261026/`。

## 1. 新数据究竟改变了什么

半决赛 3,594 张中，旧 test1 的 500 张、旧 test2 的 1,300 张均已通过映射定位；真正新增为 1,794 张。因此不能把 3,594 张全部作为新增样本，更没有新增同等数量的真实标签。

| 指标 | test1（500） | test2（1,300） | 新增（1,794） |
|---|---:|---:|---:|
| 加完整 Bstar 后，Background 预测占比 | 26.76% | 29.97% | 30.02% |
| Building | 18.04% | 17.87% | 17.10% |
| Road | 8.42% | 6.89% | 6.46% |
| Water | 8.22% | 8.61% | 9.27% |
| Barren | 1.89% | 1.88% | 2.06% |
| Vegetation | 24.47% | 22.20% | 22.35% |

**这里的面积是模型预测面积，不能称为真实类别先验，更不能用于判断过召回/欠召回。**

用固定 L2 正则的逻辑回归区分图像来源，按图像随机 70/30 划分，重复三个固定种子；标准化仅使用训练部分：

| 区分哪两组 | 18 维外观统计 AUC | H75 特征 AUC | 类别预测占比 AUC |
|---|---:|---:|---:|
| 旧 test2 / 新增 | 0.509 | 0.513 | 0.486 |
| 旧 test1＋test2 / 新增 | 0.508 | 0.509 | 0.511 |

| 源域抽样 / test2 | 0.523 | 0.789 | 0.609 |

AUC 约 0.5 表示当前分类器、当前特征难以区分两组；不证明两组所有条件分布相同。源域与新增的特征 AUC 三次为 0.821/0.809/0.776，而 test2 与新增为 0.534/0.502/0.504。

最近邻也支持类似判断：新增图到旧测试图的 H75 特征余弦距离中位数 0.01542，旧测试图之间为 0.01511；两者接近。源域到目标域的差别仍然存在，但本轮没有看到新增数据相对 test2 出现明显整体变化。

限制：尚无航线级分组，随机图像划分可能包含相邻场景；特征来自 H75 自身；相近的总体统计不排除少数困难场景。外观统计可分性低也不能否定所有纹理、尺度或局部光照问题。

**对决策的影响：** 继续使用旧目标域的成功经验有依据；“新增数据使旧方法全部失效”“必须马上换更大模型”“优先重做 FDA/重扫偏置”目前均没有这组数据支持。新增的是无标签覆盖，而不是可监督训练数据翻倍。

可视抽查：[固定随机样本与最近邻](analysis_20261026/contact_sheet_1.jpg)、[特征较新及偏置敏感样本](analysis_20261026/contact_sheet_2.jpg)。后者的高偏置敏感样本集中出现农田场景；这是样本观察，不是其预测错误的证明。

## 2. “大模型比 H75 强”的旧比较混入了校准差异

历史完整 source1399 正式 1024 评估：H75 使用 Bstar 为 77.5311，全部偏置归零为 80.4418；这两项已经有缓存和逐像素校验。本轮在同一个 256 真值网格复算：

| 模型输出 | 诊断 mIoU |
|---|---:|
| H75，D4 原始 logits，零偏置 | 80.43 |
| H75，同一 logits，完整 Bstar | 77.52 |
| M2F，已有 canonical256 语义预测 | 79.34 |

H75 是 D4，M2F 是其缓存的单尺度协议，因此这仍不是严格的纯骨干容量实验。但它足以推翻用“79.38 > 77.53”直接证明 M2F 架构更强的论证：校准协议不同可以反转排序。

这也不意味着应把线上 Bstar 清零。Bstar 的价值来自旧线上证据，而源域的最佳偏置不保证适合目标域。正确做法是把表征能力与最终决策校准分开审计。

## 3. 异构教师确有互补，但不能整体替换

本轮使用 source1399 GT，H75 D4 原生 logits 与 M2F Dpred 都放在 256 网格比较。以下是相对**无偏置 H75**的计数：

| 真值类别 | H75 错、M2F 对 | H75 对、M2F 错 |
|---|---:|---:|
| Background | 1,280,086 | 1,488,675 |
| Building | 307,614 | 457,599 |
| Road | 244,558 | 293,641 |
| Water | 38,113 | 136,125 |
| Barren | 196,509 | 101,694 |
| Vegetation | 304,450 | 688,803 |
| Agricultural | 283,448 | 178,771 |
| Vehicle | 18,921 | 21,177 |

它说明：M2F 提供了一些 H75 缺少的判断，尤其有荒地/农田召回互补；同时也会破坏很多正确像素。它不是整体替换 H75 的证据。按真值类别统计只用于诊断，实际门控不能使用目标真值类别。

理论上“知道每个像素谁正确再选择”的 oracle 会很高，但那使用了真值，不能作为可达到的成绩承诺，也不能拿其差值当 72 分的预计收益。

加 Bstar 后，上表会明显变化。这再次说明：教师能力、偏置选择和蒸馏规则相互影响；不能跨概率定义直接比较置信度或拼接规则。

## 4. HPRD 的具体问题：纠错主要落在背景，区域可靠不等于像素可靠

旧 `TEACHER_QUALITY_R1099.json` 的 `region_precision=0.99300699` 实际为：143 个区域中，142 个区域的预测类别等于该区域 GT 多数类。它不是逐像素 99.3% 精度。

旧代码还只对含接受区域的图像累计该报告的混淆矩阵，所以报告里的 85.695→85.933 不是完整 R1099 的 mIoU。R1099 本身也在历史调研中被使用过，不能称为全新盲测。

本轮首先用旧缓存复现了旧 C 教师软混合的 **18,073 纠正 / 10,664 损伤**，与旧报告完全一致，确认标签映射及统计口径。再将同一门控和区域 pH 作用到当前 H75 D4 概率上，复算 `0.75*pH75 + 0.25*pRegion`：

| R1099 非空区域图中的像素变化 | 数量 |
|---|---:|
| 纠正 H75 原错误 | 19,213 |
| 损伤 H75 原正确 | 11,501 |
| 其中纠正 Background | 19,007 |
| 其中纠正 Barren | 132 |
| 其中纠正 Agricultural | 74 |

因此，这个离线教师操作的纠错 **98.93% 是背景**。这不是训练后学生的成绩，但清楚表明当前监督方向与“重点补荒地/农田”并不一致。仅增加区域采样或权重，可能主要放大背景改动。

另外，现有门控是在 Champion C 的特征/原型体系上建立，并未重新证明对 H75 的每个类别同样可靠。训练记录中的稀疏度、完整网格归一化以及 25% 区域教师混合确实限制了有效信号；但 loss 标量大小不等于梯度大小，不能据此直接把系数放大几十倍。

### 进一步检验：简单去掉区域边缘能否解决？

| 25% 软混合，R1099 | 纠正 | 损伤 | 纠正/损伤 | 净正确像素变化 |
|---|---:|---:|---:|---:|
| 原区域 | 19,213 | 11,501 | 1.67 | +7,712 |
| 256 网格向内收缩 1 像素 | 9,626 | 4,664 | 2.06 | +4,962 |
| 收缩 2 像素 | 5,922 | 2,556 | 2.32 | +3,366 |
| 收缩 4 像素 | 3,771 | 1,409 | 2.68 | +2,362 |

边缘确实带来风险，但有效纠错也集中在那里。只看精度比，会误把“几乎不改”当成最佳方案。收缩不能单独解决有效覆盖不足；这些计数也不是 mIoU 增量。

**当前应撤回的建议：** 不把“原样增加 HPRD 有效步数”“简单提高区域权重”“直接使用纯区域标签”作为最可能冲分的主方案。需要先证明新增监督在具体冲突类别上有净纠错作用。

## 5. 历史成功方法真正共同的地方

1. 先验校准改变了少数类的决策取舍，收益由旧线上验证；它解决的是输出决策，不等于学习到了新纹理或边界。
2. 测试域自训练利用目标图像的覆盖和一致性，证明无标签目标图像有价值。不能把同源教师描述为“数学上永远无法改善”的闭环。
3. H75 对已有有效训练轨迹做参数平均，说明减少单条轨迹的波动有收益；不等于推理模型集成，也不证明再增大网络必然有效。
4. 失败的 ROUND2 同时改变教师、目标池和步数，无法分离哪一项造成无收益；“多数据无用”“多训永远无用”均超出证据。

这些成功都能指明**改变了哪些像素、影响了哪些类别、引入了什么约束**。下一方案也必须达到这个解释程度。仅增加容量、损失项或训练时长，没有足够针对性。

## 7. 新发现：真实重叠不是猜测，数据里有现成的跨图关系

全量检查 3,594 张测试图＋6,996 张源图，共 10,590 张，CPU 耗时 367 秒。方法是核验 1024 图的 256 宽边缘/256 方形角块的完整 RGB SHA256；对应观测到的 768 像素切片步长。排除低纹理块后，统计不同图像相反边缘/角块的精确匹配，并检验图关系的平移闭环。

| 已核实事实 | 数量 |
|---|---:|
| 测试图之间的精确重叠关系 | 2,670 对 |
| 至少与另一测试图重叠的图像 | 1,787 / 3,594 |
| 这些图形成的相连场景组 | 355 组，每组 2–12 张 |
| 几何闭环冲突 | 0 |
| 新增图中，与其他测试图重叠 | 864 / 1,794（48.16%） |
| 新增图中，直接与旧 test1/test2 重叠 | 651 / 1,794 |
| 新增图平均可由另一测试图观测的面积 | 21.20%（去重后的并集） |
| 当前方法检测到的源图—测试图精确重叠 | 0 |

**因此没有发现可以直接迁移源域 GT 的目标区域。** 零匹配只适用于本轮精确块匹配方法，不能否定其他位移/尺度下的全部重叠。

新的可利用信息是：同一块地面在两个不同图像上下文中被观测到，对应像素应具有同一类别。这是确定的几何对应，区别于用模型自己猜“两个区域语义相似”。

源域内部另有一个重要发现：**1,399 张内部验证图中，762 张（54.47%）与训练图共享精确像素区域**，共 1,923 对训练—验证图关系。这不是发现测试 GT 泄露；它说明当前内部验证划分并非按独立地理场景隔离。它可能造成验证偏乐观、方法排序失真，但不能单凭它证明历史负相关的全部原因。

后续诊断应同时报告“验证图有训练邻居/无训练邻居”两个子集；若重新建立训练验证划分，应按重叠图的连通场景组划分，不能只按文件名随机划分。历史模型已经接触过原训练集，重分组本身不会使其成为重新训练后的独立验证。

### 用 GT 检验：不同上下文是否真的有用？

从源域验证—验证重叠关系中，用固定种子抽取 200 对；两边重叠区的 **2,564,096 个有效 256 网格像素，GT 不一致数为 0**。读取已有 H75 D4 logits，无需再跑网络，对齐后比较：原预测、等权平均两个上下文概率、选离图像边缘较远的一侧。

这批区域只出现 Background、Building、Road、Water、Vegetation、Vehicle 六类，**没有 Barren、Agricultural**。下表固定只平均这六个 GT 出现类，不能与全八类比赛 mIoU 混用：

| 保持完整 Bstar | 原预测 | 两上下文概率平均 | 变化 |
|---|---:|---:|---:|
| Background IoU | 75.92 | 76.62 | +0.70 |
| Building IoU | 89.56 | 89.64 | +0.08 |
| Road IoU | 86.73 | 87.55 | +0.82 |
| Water IoU | 81.65 | 81.89 | +0.24 |
| Vegetation IoU | 91.97 | 92.25 | +0.28 |
| Vehicle IoU | 80.77 | 82.15 | +1.38 |
| 固定六类平均 | 84.43 | 85.02 | +0.58 |

无偏置版本的固定六类平均也从 84.66 到 85.19。只选更靠图中心的一侧，完整偏置下为 84.89，低于两上下文概率平均。

这些是匹配区域上的离线教师诊断，不是完整 source1399 指标，不是训练后学生增益，不是目标域线上预测。每块真实地面按两原视图分别计分；同一场景的图存在相关性，不能把像素数当独立统计样本。它支持具体机制，不提供 +0.58 线上承诺。

## 8. 当前最值得准备的下一候选：H75 真实重叠上下文蒸馏

**我现在的首选是利用刚验证的跨图关系，改进 H75 的目标域监督。撤回此前以源域表面分数为依据、优先直接提交 M2F 的建议。**

选择理由是三条连续的项目证据：

1. 新增与旧 test2 的整体特征、预测行为接近，旧 H75 及目标域适应经验仍有利用价值。
2. 数据中确有大量可严格对齐的不同上下文，且已建立无几何冲突的关系图，不需要新模型来猜对应关系。
3. 在有 GT 的对应区域，固定的同模型概率平均改善了六个出现类别，尤其车辆和道路；这比只凭总分、置信度或论文结果决定方向更具体。

### 实现内容

- 冻结现有 H75 作为唯一模型教师。为半决赛图缓存其正式 D4 原始 logits，再按既有规则加一次 Bstar、计算概率。不要混用本轮单视图诊断输出与正式教师缓存。
- 按已验证的整数平移对齐重叠区。1024 输入中的 768 平移对应 256 logits 网格中的 192 平移，重叠边宽为 64。
- 最小版本使用两个上下文：在精确重叠区令 `pT(x)=0.5*pH75(image,x)+0.5*pH75(neighbor,warp(x))`；其余区域仍使用本图 H75 的概率。多邻居不能直接当成“越多越好”：先固定一个几何规则选择第二视图，再用同一 source 缓存复算该实际规则；或者另行复算多邻居平均后再冻结规则。
- 学生从 H75 初始化；source GT 分支、目标池、优化器及训练预算与半决赛对照基线保持一致。延续原有 source/target 系数时为 0.1/1.0，首轮不因图像数量增长而机械延长到 5,000 步，也不同时换骨干、调 Bstar、加其他损失。
- 教师和学生的 KL 均在对称加 Bstar 的概率空间计算。实际训练只能看到官方图像和合法伪标签，不能使用本轮诊断中的“谁对谁错”选择器。
- 推理产物仍是一个学生权重；该方案的跨图处理发生在训练监督准备阶段。依赖赛事已经允许的“自有模型对测试图生成伪标签参与训练”前提，复现材料保留原始官方回复。

这不是“再加一轮同样的伪标签”。真正改变的是：相同像素的监督还参考了另一张真实图提供的周围地物信息。它更有希望处理切片边缘、车辆/道路上下文不足；**目前没有证据说明它能解决荒地/农田的系统性混淆**。

### 开训前必须做成的具体产物

1. 使用已经导出的 [精确重叠关系图](analysis_20261026/target_overlap_graph.json)，生成可复现的邻居和坐标映射；抽样核验原图 RGB 对齐及 256 网格方向。
2. 生成两上下文教师缓存后，统计每类真正发生概率变化/argmax 冲突的独立图数、区域数、面积以及 KL。不能把“21.2% 有重叠”直接称为“21.2% 有效新监督”。
3. 用固定 source 对应区核验实际实现的逐类纠正/损伤；本轮基础平均已经有正证据，但工程版本不能在邻居选择、TTA、分辨率上悄悄改变定义。
4. 在短批次中检查改变区域的梯度贡献，避免再次出现“名义上有新教师，实际被全图平均和 anchor 淹没”。若信号近零，先修监督实现，不提交一个几乎没变的学生；不能通过未经测量地放大系数来解决。

这些工作不消耗线上名额；它们使候选先具备可解释的改动，再由下一次真实分数决定后续。队友正在训练的实验无需因本报告中断，我方可以准备上述教师缓存和实现核验，避免重复训练。

当前尚未拿到本阶段 H75 线上基线、队友当前具体实验配置。72 仍是目标，不能把旧 test2 的 71.3294 直接当成新阶段基线，更不能据本轮局部 +0.58 推算线上必达 72。

### 为什么暂不优先其他方向

- **更大模型**：保留冻结骨干/小适配器研究资格；新增无标签数量和失配的源域总分不足以支持立即全量换架构。
- **原样加强 HPRD**：其当前实际纠错高度集中背景；先解决类间纠错选择，不能只增加覆盖或更新次数。
- **FDA/颜色变换**：本轮没有显示新增相对旧 test2 的明显整体外观改变，优先级低；不是宣布所有外观适应永远无效。
- **纯随机 global/local 裁剪**：本轮找到了真实跨图对应，它提供更具体的上下文监督依据。裁剪方案是否有效仍应看队友的当前实测，不用一般理论提前判胜负。
- **盲目重扫 Bstar**：保留既有线上证据；当前预测面积与域 AUC 都不能给出目标真值或最佳偏置。
