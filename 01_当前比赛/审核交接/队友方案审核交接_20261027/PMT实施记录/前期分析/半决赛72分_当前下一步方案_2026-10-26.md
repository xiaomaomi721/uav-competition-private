## 3. 五份队友材料改变了哪些判断

### HPRD已做完，不能原样再做

10月14日的H75_HPRD_V1已从H75初始化、用H75锚定完成1000次有效更新，已合并权重并生成旧test2包。只有source成绩77.536042%，本轮没有发现它的有效半决赛线上结果。10月21日“先做H75起点HPRD”的建议已被这一执行事实补上。

10月24日补测H75 source为77.531149%，两者数值只差约+0.004893个百分点。由于历史评估TF32等设置仍需统一，这只能是数值比较，不能包装成严格受控增益，更不能预测线上。

### 稀疏监督之外，还存在明确的损失缩小机制

本轮已读取实际`code/hrpd_train.py`，确认：

```text
区域教师 pT = 0.75*pH75 + 0.25*pRegion
区域loss = sum_R KL / (256*256)
区域外anchor = mean_notR KL
总loss = 0.1*source_CE + ramp*region_KL + 0.15*anchor_KL
```

它不是“区域内均值”。我10月21日对剂量的讨论必须按这个事实修正。

1000步真实日志汇总：

| 指标 | 结果 |
|---|---:|
| 区域非空步数 | 103/1000 |
| 全程平均区域覆盖 | 1.713831% |
| 累计区域像素访问 | 1,123,176 |
| 按ramp加权的面积预算Σ ramp×区域比例 | 12.735773 |
| 平均0.1×source CE | 0.0142548481 |
| 平均ramp×region KL | 0.0001595380 |
| 平均0.15×anchor KL | 0.0000742387 |

损失数值不能直接换算成参数梯度贡献。但全网格分母、稀疏区域、25%区域教师占比共同说明：新增纠正信号受到多重限制，“LoRA存在且参数变了”远远不等于充分学到了异构知识。

本轮读取的`TARGET_SUPPORT.json`还有更准确的独立统计：125张图、128个合格query，其中Background90、Barren23、Agricultural15。其他五类本来就不在允许类别集合`{0,4,6}`内；车辆为零是方法的范围限制，不能说只是没抽到。

这使“将有效区域证据用得更充分”成为合理的后续训练方向，但不能由小loss直接推断放大它必涨分。若后续执行，应先保持gate、teacher、全网格分母不变，只改变采样或剂量中的一个。匹配预算应含ramp、区域面积及实际成功更新；不能直接把历史0.103当成新实验缩放系数。

### 四条实验线并未证明大模型路线失败

- CSL-PCOS、ALHVR V1/V2/V3是离线教师／门控诊断，没有形成新的学生线上成绩。
- ALHVR V3保护约99.99739%的G，基本取消了纠正动作，不能据此宣称“新知识完全无用”。
- M2F的B1反馈模块只显示非常小的source增量，ON/OFF几乎不改变预测。这否定的是当前模块的有效作用证据，不是否定原始M2F模型。
- 现在GPU1运行的是后续pair-loss分支，不等同于已有30k基础模型已完成线上检验。

### GLOBAL_LOCAL可以试，但不作为当前第一候选

该方案是source整图CE加640裁剪放大到1024的CE；局部项在总loss中权重0.025。它没有新的高分辨率融合网络，也没有局部推理拼接。插值放大能改变物体在特征图上的尺度，不能创造新细节。

均匀选窗口还会改变像素曝光：1024图中所有640窗口共有中心256×256，中心总会进入局部监督。因此TREAT−DUPLICATE检验的是crop-resize整体作用，不能全部归因“纯尺度”。

它目前仍把target写成旧1300张、把71.3294作为最终门槛，这两点必须更新。源域分数和第二seed只用来检验机制／健康，不能自动决定半决赛排名。HRDA的原生高分辨率局部＋低分辨率上下文＋尺度注意力是另一种完整机制，不应混称。[HRDA原论文](https://www.ecva.net/papers/eccv_2022/papers_ECCV/html/1999_ECCV_2022_paper.php)

### Zero Bias说明偏置值得检验，但没有指出目标域方向

source1399上Zero Bias比旧Bstar高2.9106个百分点，主要来自Barren／Agricultural误报减少，同时它们的漏报增加。bootstrap只覆盖该开发集的采样不确定性，不覆盖到半决赛的域迁移。

旧数据仍占1800/3594，且偏置曾有目标域正例。直接去零存在丢掉旧域校准的风险；固定0.5收缩也只是没有目标真值支持的折中，不是数据推导的最优值。因此它们保留为之后根据线上结果选择的候选，本轮不把它们当作达到72的主承诺。

## 4. 为什么当前选择M2F直接单模型

它直接检验现有资源中尚未被回答的问题：**完整的异构分割模型，是否比通过少量区域蒸馏进入B3后的结果更适合新半决赛。**

选择依据：

1. 已有官方数据训练的30k模型和完整部署配置，避免把时间先花在下载新骨干和重做环境。
2. 不经过HPRD的125图／128query筛选限制，也不受B3 Stage3低秩更新表达范围限制。
3. 不需要假设新数据应该保留、减半还是撤销B3的旧偏置。
4. 完整架构在当前半决赛尚无有效线上结果；现有负例主要来自蒸馏、source反馈模块或门控诊断，不能替代这次验证。

最强反对理由也要保留：H75已经针对test2做过适配，M2F主要从source训练而来，新集合仍有1800张旧图，因此M2F可能损失已有目标域优势。M2F source约79.38不能与带Bstar的H75 source77.53直接推出线上强弱；H75去偏置source甚至约80.44，更说明source排行榜不能代替本次目标评估。

因此这是我选择的**下一项有结构性突破空间且可立即准备的候选**，不承诺超过H75或必达72。

## 6. 大模型旧结论应如何更新

现在增加的是1794张新的无标签图像；相对H75过去用的1300张target，完整可用目标池是3594张。带GT的source5597并没有因此增加。

所以需要同时保留两点：

- 新目标图能增加场景覆盖和适配信号，原来的某些target-only结论值得重新检验。
- 它没有自动解除大模型全量微调的过拟合、错误伪标签和优化问题；不能用“总图数增加”直接推翻以前B4/B5全参训练的负例。

过去“大模型不行”的概括应撤销。准确表述是某些更大骨干在当时配方下没有成功。下一步先验证现有M2F；若仍需要引入新的预训练表示，冻结DINOv3骨干＋小头／少量适配参数值得恢复为候选，而不是立即全量重训。

[DINOv3官方仓库](https://github.com/facebookresearch/dinov3)提供冻结特征分割评估；[Rein论文](https://openaccess.thecvf.com/content/CVPR2024/papers/Wei_Stronger_Fewer__Superior_Harnessing_Vision_Foundation_Models_for_Domain_CVPR_2024_paper.pdf)支持在其领域泛化分割基准上用少量适配参数利用大模型。两者都不是本航拍任务的收益保证，也不据此马上扩展本轮候选列表。

## 7. 收到成绩后怎样调整

只定义决策条件，不预占后续提交名额：

- **任一单模型达到72：** 保存该模型、代码、配置、数据清单、ZIP SHA和回执；目标达到，再讨论是否继续提升。
- **M2F高于H75但未到72：** 将M2F设为新的当前基线，下一项优先考虑对新3594张的受限目标适配；不自动继续把所有知识压回B3。
- **M2F低于H75：** 不宣布所有大模型失败。结合二者分歧和现有区域证据，决定下一步是H75校准，还是HPRD纠正强度实验；不在看分前锁死选择。
- **两者都明显低于72：** 先排除新集的打包／标签／预处理问题，再用新基线实际差距调整方案；不能拿旧71.3294解释差距。

无目标GT时，这次线上比较也不能说明具体哪一类上涨；分歧图和面积统计只能辅助提出下一项假设。每轮只记录预先明确的候选、身份与机制，结果出来后再决策。
