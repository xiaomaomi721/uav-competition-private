## 三、所有新任务的安全要求

在每次新开 SSH 会话或启动实验命令时，显式设置：

```bash
umask 077
```

这样新建文件和目录默认不会向组用户或其他用户开放访问。

执行训练、推理或诊断时：
- 新日志、JSON、预测结果、权重及缓存优先写入受保护的专属目录。
- 不要在 `/data/uav/code`、`/data/uav/datasets` 等共享目录直接存放新的敏感实验资产。
- 不要执行针对 `/data/uav` 的递归 `chmod` 或 `chown`。
- 不要覆盖已有结果；每次新实验使用独立目录。
- 不要把模型权重、教师缓存、训练配置或完整实验日志发送到公共目录。

以下问题尚未解决：

3. 部分教师权重仍位于可被其他用户读取的共享路径：
   - `/data/uav/checkpoints/A05_WEIGHT_alpha05.pt`
   - `/data/uav/checkpoints/TREAT_blindrecall_step2000.pt`
4. `/data/uav/code`、`/data/uav/datasets` 等共享目录尚未整体加固。

这些路径涉及共享资源，禁止擅自递归修改权限。应由服务器管理员确认所有权和使用关系后再处理。

## 五、团队协作注意事项

当前四个目录是 user2 专属目录。其他队友不要假设自己能访问，也不要为了方便直接把权限改回 `775`。

如果队友需要共同访问代码、配置或结果，应先确认各自的 Linux 账号及所属用户组，再建立独立的团队共享目录，并通过受控的组权限或 ACL 授权。

**最终原则：敏感资产默认私有，需要共享时单独授权；共享 GPU 不等于共享文件权限。**
