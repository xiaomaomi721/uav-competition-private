## 0. 一页决策

**主路线：** H75 固定基线 → 3594 张正式推理/打包链路 → H75+Bstar / Zero Bias 两个预设候选 → CPU-only 教师有效性审计 → 若通过则 CTRL + ACDD-3594 最小配对训练 → 符合准入条件的候选线上验证 → 交付。

**非主线：** EMA-ACR/T12、多种 bias 网格扫描、额外教师/复杂结构、人工标注。ACDD 不可行时**不自动**改做 EMA-ACR。

**核心训练设定（待代码核实后冻结）：** 源域 5597 张；去重目标域 3594 张（旧 1800、新 1794），旧新采样约 50:50；H75 初始化；首次两臂 CTRL 与 ACDD-3594；2000 optimizer updates 仅为筛选预算。**所有训练步骤需用户单独批准。**

**现时最急阻塞：** 3594 包装器不存在；GPU1 已被其他任务占用（Claude 审计时 85% 利用率）；新增 2294 张的教师缓存缺失；双教师相对 H75 的源域校准一致审计尚未执行；H75 参数平均的书面许可缺失。

## 4. P2-CPU：双教师有效性与 bias 一致性审计（与 P0-A 并行）

**目标：** 决定是否值得从 H75 再进行一次 ACDD 蒸馏，且不把原有不同 bias 协议导致的差异误判成 donor 独立知识。**此阶段只读即可实施，不需要 GPU。**

### 输入锁定

- source1399 官方/项目 split 与 GT（来源及标签/ignore 映射逐项核验）；
- H75 `8×256×256 FP32` pre-Bstar logits、对应 PNG 预测及原始评估记录；
- Arm B 使用 **H75 冻结正确配置**形成的 source1399 pB 缓存（FP16、**含 Bstar**）；
- donor `iter_30000.pth` 对应的 pD 缓存（不是 E02 用的 `best_mIoU_iter_30000.pth`）；
- Bstar 向量、H75 M/G 生成函数、上采样/对齐策略、`SOURCE_AUDIT_SPLIT`。

### 必须正确处理的技术细节

1. 对 Arm B 使用两套概率：含 Bstar 的原 pB，及 `softmax(log(pB)-b)` 恢复的近似 zero-bias 概率；FP16 下浮、零值和舍入导致非严格等价，须记录数值误差。**更准确的 raw 对照留到获准 GPU 后再考虑，不阻止先做 CPU 审计。**
2. 分别用两套 pB 重新计算 `M`、`G`（遵守原训练分辨率、1024 → 256 block pooling 等实现）；禁止简单从已经混合的 pT 里减 bias。
3. 计算 ArmB+Bstar、ArmB+Zero、donor、mixed-original、mixed-zero、H75+Bstar、H75+Zero 的**同坐标、同有效像素、同决策规则**全图 mIoU、各类 IoU、Precision/Recall、NLL、Brier；报告可能存在的预测分辨率/校准协议不对等。
4. 在 `M/G/non-G/M∩G` 报告覆盖率、类别构成及相对于 **H75 学生**的 corrected/harmed pixels、分歧/一致率、软概率 KL/NLL/Brier。
5. 做 H75-base **硬预测替换反事实**：仅在 G、仅在 M、M∪G、原 gate 规则中使用教师预测，其余保留 H75 预测；重算全图 mIoU 与各类变化。**这一结果是“硬替换效果”，不是蒸馏训练后的严格上限。**
6. 用图像为单位进行配对 bootstrap（建议可先低次数试运行，正式不超过 5000 次），避免逐像素独立的错误假设；统计可使用按图像缓存的混淆矩阵以控制 CPU/内存。
7. 加入 **mixed teacher vs H75** 的软目标质量与硬预测差距；不能只比较 mixed vs Arm B。source1399 属于历史复用集，不能推断 test3 真正 mIoU。

### P2-CPU 交付

- `teacher_audit_summary.md`：一页摘要，区分事实、技术推断和缺失项。
- `teacher_audit_metrics.json`：全图/分组/逐类/区域指标及 bootstrap。
- `teacher_audit_bias_matrix.csv`：各教师、学生、两套 bias 与重算 M/G 的比较。
- `teacher_audit_manifest.json`：cache checkpoint SHA、输入数量、GT valid/ignore、原始脚本配置哈希、统计版本与处理顺序。

**解释原则：** donor 净纠错为正 / NLL 更低可支持继续尝试，但不能保证新域真实提升；硬替换不足 +1pp 并不自动否决训练。若 mixed 对 H75 主要弱类持续显著变差、无新增软监督信息、或正确 donor 缓存不存在，应建议 NO-GO 并报告具体证据。

## 5. P1：H75 推理校准线上 A/B（依赖 P0-B）

预先冻结两个部署候选：

- **B0：** `H75 + D4 TTA8 + 原始 Bstar`；
- **B1：** `H75 + D4 TTA8 + Zero Bias`。

两组仅改变固定 bias，checkpoint、输入、颜色预处理、TTA、logits 累积、插值、标签映射、文件名、ZIP 完全一致。source1399 的 77.5311 与 80.4418 是**源域**参照，不能代替半决赛线上验证。

优先一次共享 GPU 模型前向、保留 logits/中间统计（**仅当磁盘和数据管理可承受**），避免不必要的重复 D4 TTA8；不存巨量全分辨率 FP32 logits，采取流式生成或可复用的低分辨率 logits 缓存。若重用机制引入额外工程风险，则采用两个安全独立推理流程。

- 线上候选须在提交前锁定参数/哈希、完整 QA；记录时间、平台原始评分/回执、候选身份。
- 每日 2 次限额及“全阶段最高分”按平台当期规则核实；排行榜反馈能否用于后续优化的边界继续单独确认，勿推导“反复调 bias 合规”。
- 不保证 Zero Bias 线上提分；如它较差，则保留 Bstar，不因源域指标较高强行更换。

## 6. P3：仅在通过 P0/P2 条件后实施最小训练

### 6.1 实验矩阵（最多两个训练臂）

| 项目 | CTRL（对照） | ACDD-3594（唯一主训练臂） |
|---|---|---|
| 初始化 | H75 独立载入；新建优化器/调度器/AMP | 相同 H75；独立重置相应状态 |
| 源域 | 固定 `train.txt` 5597 张；严格排除 source1399 | 完全相同源域清单、采样流 |
| 目标域 | 无 | 去重 3594：旧 1800 / 新 1794，目标采样约 50:50 |
| loss | `0.1 × L_source`（待原 H75 配置核对） | 原 ACDD `0.1L_source + ramp·L_target + 0.15L_anchor`（以代码为准，确认 anchor 是否随 ramp） |
| 教师 | 无 | Arm B+正确冻结 donor `iter_30000.pth`，原 pB/pD/M/G recipe |
| 范围 | 与 H75 原 ACDD 可训练层对齐 | stage2/stage3/decode_head；审计约 44,336,200 params，代码核验为准 |
| budget | 2000 **effective** updates 为目标 | 2000 **effective** updates 为目标 |
| snapshot | 500/1000/2000；禁止事后只挑最高源域分 | 同样；记录 attempted/AMP skipped/effective |
| 主问题 | 多看源域是否改善 H75 | ACDD 整体方案是否胜过 H75；相较 CTRL 是否有增量 |

**对照解释边界：** CTRL 不能严格隔离 donor、anchor、目标数据、BN 和额外计算等各因素；ACDD vs CTRL 是目标适配整体 treatment 效应，而不是“新增 1794 张的纯因果效应”。不要额外为了形式完美引入第三、第四组。

**采样注意：** 一个 source batch 与一个 target batch 不等于 loss 相同尺度；严格冻结 source/target 采样、原代码 loss reductions、学习率、梯度累积、BN/buffers 策略，记录实际覆盖张数和旧/新有效更新。旧 1800/新 1794 的 50:50 是遗忘风险对冲，**不是已证明最佳分布**。

### 6.2 训练前工程步骤与健康检查

1. 在独立 H76 工作区构建 target 数据加载器/manifest；旧缓存 test2 1300 可复用时必须确认正确教师、Bstar 语义、空间对齐及 schema 一致；新增 test1 500 + test3-new 1794 需要 **2294 张**教师缓存。
2. 从 H75 `model` 严格加载；不能把 checkpoint 内 `step=1000` 当成继续原 optimizer state；新的 AdamW/scheduler/scaler 从 step 0 开始，并记录初始化参数哈希。
3. 固定真实配置快照：学习率、weight decay、betas、梯度裁剪、loss 系数/ramp、AMP、BN、采样器 RNG 与恢复状态；标签训练内部 0–7，提交 1–8，ignore 按代码确认。
4. 先做 **100–200 effective updates 冒烟**：检查标签值域、NaN、inf、loss、梯度、BN、M/G、空掩码处理、缓存读取、checkpoint 恢复、GPU 峰值；之后最多到 500 步健康检查。
5. 对后续是否继续训练使用**梯度/稳定性 + 源域风险 + 旧新目标域无标签分布**综合判断，不把未标注统计当 mIoU。
6. 若任一模型最终候选通过本地安全性筛查，再做统一 D4 TTA8 全量源域验证与有限线上提交；评估级别分为固定小子集筛查、全量 source、目标域正式提交。

### 6.3 建议 GO / STOP 规则（非官方门槛）

**允许进入训练准备：** P0 可提交基线已在 GPU 窗口完成或其剩余操作有可靠、已批准的窗口与时间保障；教师源域审计在同协议下显示可信的纠错或软监督信号且无显著弱类伤害；正确 donor/教师资产齐全；GPU1 经确认可用；新增缓存与独立包装脚本可实施。

**立即 STOP / 回退：** 官方限制或参数平均合规性被否定；资源抢占风险；manifest/label/尺寸错位；NaN、OOM、无法重现或 checkpoint 加载不兼容；关键类别严重坍缩；需要覆盖 H75 原文件；时间不足以完成有效提交与材料。

**候选筛选：** 80.4418% 是 H75+Zero 的**源域强参照**而非硬一票否决值。源域小幅下降可在目标侧诊断稳健、提交配额有余时考虑线上验证；若源域整体下跌约 1pp 以上或重点类别明显退化，原则上不投入有限名额。所有阈值为预先冻结的启发式警报，非目标域精度证据。

**避免伪精确：** 不强设教师硬替换 `≥1pp` 的 GO 阈值、`<0.5pp` 的 STOP 阈值；不把无标签类别比例靠近 source GT 当作更准的证明；不把单一 seed 的 0.1pp 差异视为可复现进步。
