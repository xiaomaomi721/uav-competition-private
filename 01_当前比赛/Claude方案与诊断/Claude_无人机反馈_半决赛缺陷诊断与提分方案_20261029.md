## 0. 结论

1. **本赛段所有模型改动没涨分，有两个共同原因，都不是“方法本身不行”。**
   - **校准混杂（实测）**：每个新模型都直接套用为 H75 调出来的 Bstar。四个已评分的失败候选在 Target 上都比冠军多预测 Background、少预测 Agricultural，漂移越大掉分越多（见 §2.1 表）。所以“新模型更差”和“新模型的 logit 平衡不同、Bstar 不再对它最优”这两件事从没被分开过。
   - **教师不比学生强（代码）**：T3_FULL_ST 的教师是 Arm B（复赛 71.045，低于 H75 的 71.329）；C1 的教师就是 H75 自己的 D4 输出，而部署时本来就用 D4；CTRL 没有教师。没有一次实验给学生提供了 H75 不知道的信息。
2. **教师的错误多数是高置信、系统性的（实测）**，置信度和 D4 一致性过滤挡不住。所以“换软/硬标签”“调阈值”不会改变结果；只有引入和教师错误不相关的监督（带 GT 的 Source 内容放进 Target 外观里）才可能纠错。
3. **10-29 上午方案的主线“测试时放大 1.5x”与本项目历史证据相反**：同一模型单尺度 0.75x/1.25x 线上分别掉 0.66/1.13pp。我们的模型在 1024 整图、无尺度增广下训练，和 MLCAS 冠军（512 crop 训练）条件不同。不建议花提交名额。
4. **今晚已实际执行（不是计划）**：①对 C1、CTRL 两个已评分模型重新缓存 Target 原始 logits，做“类别面积对齐”重新校准；②实现并启动一组新训练（C1 + 偏置一致 ClassMix + 风格迁移），2 个强度 × 2 个 seed，跑完做权重平均。结果见 §6。
5. **我不承诺涨分。** 二等奖线约 71.35–71.41，需要 +0.35pp 以上；以下每个候选我都写清楚它能检验什么、失败时说明什么。

## 1. 赛题原文要点与真正难点

### 1.1 原文约束（`03_历史文档/文档归档/01_赛题与规则/`）
- 官方点名的难点：多源数据跨域、类别分布不均（“部分类别在测试集中占比显著高于训练集”，举例农田、水体）、目标尺度差异大、标注噪声；测试数据分三次发布，**要求在不同子集上都保持性能**。

- **主误差方向是“真实类被吃进 Background”**。H75 去掉 Bstar 后线上 −3.02pp，像素变化里最大的是 Agricultural→Background 3.02%、Barren→Background 1.08%（`aic2026_presence_calib_20261029/out/EVAL_VAL_RESULT.json`）。

- **外观聚类（实测，K-means 按清晰度、饱和度、灰度方差聚类）**：Target 里“高饱和绿色调”一簇占 26.2%，Source 只有 17.5%。这一簇里 Source GT 是 Vegetation 56.4%、Background 21.0%；冠军在 Target 同簇预测 Background 45.6%、Vegetation 26.6%。被判成 Background 的 Target 像素平均 RGB 是 (71, 83, 86)，偏暗蓝绿，**既不像 Source 的 Background (108, 110, 98)，也不像 Source 的 Vegetation (82, 89, 54)**。这些像素的教师可靠性权重均值 0.918（C1 的 a²(1−H)），几乎满权重。没有 GT，不能断言它们全错；但可以断言：**如果它们错了，现有任何置信度/一致性过滤都挡不住。**
- 真实失败样例（`fail_sheet.jpg`）：test3_1833 有一条清晰的弯曲道路，冠军全判 Background；test3_965 村庄四周大片树林，冠军全判 Background。

## 2. 已有方案的具体缺陷（逐个对代码）

### 2.1 共同缺陷一：校准混杂（实测）

四个失败候选 vs 冠军，在 Target3594 上逐像素对比（`zip_compare_out.json`）：

| 候选 | 线上 Δ | 与冠军不同像素 | Background 面积 | Agricultural 面积 | 最大的类别迁移 |
|---|---:|---:|---:|---:|---|
| 冠军 H75+Bstar | 0 | 0 | 29.66% | 12.02% | — |
| C1 | −0.091 | 1.77% | 30.04% | 11.62% | Agri→Bg 0.35% |
| CTRL | −0.680 | 3.22% | 31.73% | 11.36% | Agri→Bg 0.76%，Water→Bg 0.49% |
| H75 Agri 置 0 | 未提交 | 3.12% | 32.17% | 8.90% | Agri→Bg 2.50% |
| M2F E02 | −3.375 | 13.40% | 35.65% | 9.30% | Agri→Bg 3.42%，Veg→Bg 1.76% |

所有退步都朝同一个方向：Target 上 Background 变多。原因（推断，有代码支撑）：这些模型都在 Source 上继续做 CE（C1 权重 1.0，CTRL 只有 Source），把 logit 拉回 Source 的类别先验；Bstar 是对 H75 的 logit 调的，固定不变地套到新模型上就补偿不足。**CTRL 在 Source 上 +1.59、线上 −0.68，与这个机制完全一致。** 所以本赛段“模型改动都无效”的结论还不能成立：模型质量和校准偏移被混在了一起。

### 2.2 T3_FULL_ST（线上 70.990，−0.009）——教师比学生弱
- 代码 `experiments/T3_FULL_ST_20261027_import/code/train_joint.py:219`：`pT = where(G, 0.75*pB + 0.25*pD, pB)`。pB 来自 `teachers/ArmB_checkpoint_step2000.pt`，pD 来自 M2F iter_30000。
- 实测 G（donor 区）平均只占 3.6% 像素，其余 96.4% 的目标就是 Arm B。Arm B 复赛 71.045，低于 H75 的 71.329。把 H75 往 Arm B 拉，结果持平略低是预期内的，**不能当作“test3 全覆盖自训练无效”的证据**。
- 当年 ACDD 用这个配方有效，是因为那时学生就是 Arm B 本身（教师 = 初始化），H75 出来后这个前提已经不存在。

### 2.3 可靠教师蒸馏 C1（线上 70.908，−0.091）——自蒸馏 + Source 拉力
- 代码 `reliable_kd_20261028/rkd_train.py`：教师是 H75 的 D4+Bstar 输出；学生用单视角 + 光度增强去拟合。部署时学生本来也用 D4，所以教师信息几乎全是学生已有的。
- 损失权重 `CE_src 1.0 + 0.1·anchor + 0.2·target`：Source 监督占主导，见 §2.1 的漂移。
- head 学习率 5e-7（主干的 1/20），Stage0/1 冻结，3594 步 batch 1：类别先验几乎只能通过特征间接变化。
- C1 与 C0 的唯一差别是像素权重 w=a²(1−H)；在 §1.3 那类高置信错误上 w≈0.92，权重改不动它们。C1−C0 Source 只差 +0.04pp，符合这一点。

### 2.4 CTRL（线上 70.319，−0.680）——纯 Source 续训
- 没有 Target 信号，漂移最大（Background +2.07pp 面积）。复赛已有同样结论：BlindRecall CONTROL 纯 Source 续训 −0.50pp。
- 队友《正确训练范式方案》建议“从 CTRL 起点继续做域适应”，前提是“CTRL 更强”；线上 −0.68 已经否定了这个前提（至少在 Bstar 下）。

### 2.5 其他方案
- **M2F E02（67.624）**：单尺度、无 TTA、无 bias，只和 H75 Zero（67.98）同口径；没有做过校准就不能判定 M2F 更弱，但也没有证据更强。它的 Target 面积漂移最大（Background 35.7%）。
- **ST++ Lite V2**：最严格的规则只改了 1 张图 4 个像素，相当于没有干预。
- **DINOv3-L+PMT（Source 68.53）**：只训了计划的 2000/8000 步（1.43 个 epoch），主干冻结，无光度/尺度增广，patch16 在 1024 输入上只有 64×64 token。是训练不足，不是 VFM 路线的证据；但 3 天内重训到能打 H75 的把握很低。
- **测试时放大（10-29 方案主线）**：见 §0 第 3 条，历史包 37/38 在线上直接证伪，并且 10-29 的 zoom pilot 只看了 3 张图、没有任何精度验证。
- **FDA+LoRA**：只做了预检，没有正式训练。我今晚实测发现，论文参数 β=0.01 的振幅交换在我们的数据上会产生明显彩色斑块（无人机图和卫星图的低频结构差异太大），见 `mixviz.jpg`。所以直接照搬论文参数确实会失败，问题在参数，不在思路。

## 3. 对你几个想法的回答

**换更强的教师/加教师？** 手里没有在 Target 上被证明强于 H75+Bstar 的教师：Arm B 更弱；M2F、DINOv3-L 都没有可比的强证据；CTRL 线上更差。几个弱教师取平均只会把 H75 往下拉。训练一个真正更强的新教师需要几天，而且如果它真的更强，直接提交它比蒸馏更省事。3 天内我不押这条路。

**让学生避免学到教师的错误？** 置信度/一致性过滤只能挡住“不稳定”的错，挡不住“稳定的错”。§1.3 那类像素权重 0.918，过滤不掉。要纠正这类错，监督必须来自和教师错误无关的地方。我们唯一可靠的这类信号是 **Source GT**，问题是 Source 图的外观和上下文和 Target 不一样。所以我的做法是：**把带 GT 的 Source 内容（按类别整块贴，ClassMix）经过颜色风格迁移贴进真实 Target 图里**，让模型在 Target 的外观和上下文里看到正确答案；其余像素仍然学 H75 教师。这是 DACS（Tranheden 等，WACV 2021）的跨域混合思想，DAFormer/MIC 都以它为基础；本项目从未实现过。

**训练集 5597 张、测试集 3594 张，模型没适应测试域？** 适应本身是有效的：复赛 BlindRecall TREAT 相对纯 Source CONTROL 净 +0.595pp。本赛段失败的原因是 §2 的教师和校准问题，不是“适应没用”。

**软标签/硬标签/自监督效果不好？** 软标签和硬标签只是同一份教师信息的两种写法，换写法不会带来新信息。TargetSSL 只训了 300 步，而且只训 Stage0/1，结论只覆盖那个配置。

## 4. 提分方案

### A 线：零训练的重新校准（用于给所有新模型“去混杂”）

**做法**：对候选模型缓存 Target3594 的 D4 原始 logits，拟合一个 8 维 bias，使它在 Target 上每类的预测面积等于冠军（H75+Bstar）的面积。Background 固定为 −0.2（argmax 对整体平移不变，所以只有 7 个自由度）。迭代 `b_k += 0.7·(log A*_k − log A_k(b))`，误差 <0.2% 停止。

**依据**：Bstar 是线上调出来的，冠军的 Target 面积分布是我们手里唯一经过平台验证的“好先验”。新模型和 H75 的差别有两部分：逐像素排序能力，和整体类别平衡。面积对齐去掉后者，留下前者。这只用到模型自己在 Target 上的预测，不用任何 Target 标签，是固定 bias，属于老师已确认的范围。

**能检验什么**：C1 对齐后如果超过 70.9987，说明 C1 的排序能力本来就比 H75 好，之前是被 Bstar 拖累；如果仍低，说明 Target 自蒸馏这个配方本身不行。不论哪种结果，后面所有新模型都应该这样校准再交，否则又会重复本赛段的混杂。

**正在做**：C1、CTRL 两个已评分模型的原始 logits 缓存（GPU0/GPU1）和拟合器自检（从 0 开始能否找回 Bstar）。

### B 线：主训练——C1 + 偏置一致 ClassMix + 风格迁移（已实现并在跑）

代码 `mix_train.py`。为了让结果能归因，**除 Target 分支外与已评分的 C1 完全相同**（同一份 H75 D4 教师缓存、同学习率/冻结层/步数/AMP/种子方案）。

每一步的 Target 分支：
1. 取本步的 Source 图和 GT（与 Source 分支同一张），随机选它 GT 里一半的类别作为掩码 M（DACS 做法）。
2. 把 Source 图做逐通道均值/方差迁移，颜色统计对齐到本步的 Target 图。
3. 混合图 = M 区域贴风格化 Source，其余是 Target 原图；再做与 C1 相同的 D4 视角 + 强光度增广。
4. 损失：M 区域用 Source GT 做 CE，**作用在 z+Bstar 上**；非 M 区域保持 C1 原来的 a²(1−H) 加权 KL。

**“偏置一致”这一点是专门为本项目设计的**：部署时输出是 z+Bstar，贴进 Target 图的像素也会被这样打分。用 z+Bstar 计算 CE，模型就能学到“在 Target 外观下，哪些地方 Bstar 补偿过头、哪些地方不够”，相当于学到一个随场景变化的 bias，这是固定 8 维 bias 表达不了的。Source 分支保持原样（未风格化的 Source 图，原始 z 上的 CE），两种情况不冲突：Source 外观对应 z，Target 外观对应 z+b。

**参数和依据**

| 参数 | 值 | 依据 |
|---|---|---|
| lr / head lr / wd / 可训练层 / 步数 / warmup | 1e-5 / 5e-7 / 0.01 / Stage2-3+head / 3594 / 20% | 与 C1 完全相同，保证唯一变量是 Target 分支 |
| 贴图类别比例 | 一半 | DACS 原文设置 |
| 风格迁移 | 逐通道均值/方差，std 比限制在 [0.5, 2] | 论文 FDA β=0.01 实测出斑块后改用它的“只换直流分量”极限；Source/Target 灰度 std 的 10–90% 分位为 21–52，比值不超过约 2.5 |
| Target 损失权重 λ_t | **0.2 与 1.0 两臂** | 0.2 = C1 原值（可直接对比）；1.0 = DACS/DAFormer 惯例（混合图损失与 Source 损失等权）。λ_t 是本次唯一不确定的旋钮，所以两点都跑 |
| seed | 每臂 2 个（20261028, 20261105） | 用来做权重平均。依据：H75 本身就是同配方多条轨迹的参数平均，线上 +0.171pp |
| 部署 | 两 seed 等权平均成单一 checkpoint → D4 → A 线面积对齐 bias | 平均合规（09-18 答复）；对齐见 A 线 |

单次训练约 40 分钟（实测 0.7 秒/步），4 张卡空闲，算力不是瓶颈。

**我对 B 线的真实预期**：它是本项目第一次给学生加入“和教师错误无关的监督”，机制上比 C1/T3 更有理由涨分。但历史上的训练类改动线上大多在 ±0.2pp 以内，所以这一臂超过冠军的概率我估计不到一半。超过之后再看是否继续加步数或加臂。

### C 线：H75 的 Barren 单轴重扫（低成本，备选）
Barren=3.6 在本赛段从未线上验证，存在性代理显示 Barren 多 158 张图。队友今天已经做好 Barren 2.6 / 3.4 / 3.8 的包（`aic2026_presence_calib_20261029/zip/`、`aic2026_h75_bias_reexplore_20261029/C_phase/`）。这是一维扫描，结果能直接叠加到 A 线的面积目标上。预期影响在 ±0.2pp 内。

### 明确不做的
测试时放大 / 多尺度（历史已证伪）；继续调 Veg/Road bias（历史包 ax5 Veg −0.4 / +0.4 线上 69.2623 / 69.2505，只差 0.012pp，对 Veg bias 不敏感；Road 的缺口在 bias 范围内不动）；从 CTRL 起点继续训；短时间重训 DINOv3/M2F 新架构。

## 7. 风险与边界

- **面积对齐的假设**：它把冠军的 Target 面积当作“正确的类别平衡”。如果新模型真的在某一类上比 H75 更准（例如真实 Agricultural 更多），对齐会把这部分收益抹掉一部分。这是去混杂的代价，我认为可以接受，因为冠军面积是唯一经过平台验证的。
- **合规**：面积对齐只用模型自己对 Target 图的预测，产出一个固定 8 维 bias，和 Bstar 同类；没有用任何 Target 标签，也没有用官网出现图数表。MIX 训练用了无标签 Target 图和 H75 教师，在 09-15 官方答疑允许范围内；两 seed 平均成一个权重，在 09-18 答复范围内。
- **复现**：MIX 的教师是 H75，H75 自己的祖先链（A05→Arm B→ACDD→R05–R07）还没有完整取证。如果最后提交 MIX，复现链会比 H75 多一层，技术报告要写清楚。
- **Source1399 只做崩坏检测**，不用来选模型；已知它与 Target 排序相反。
- 二等奖线 71.35–71.41 是根据零散名次推算的，需要你看排行榜确认。
