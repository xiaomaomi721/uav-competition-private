## 4. H75冠军链：今日一切新实验的保底参照

### 4.1 模型身份与本赛段已验证协议

- 最终模型：**SegFormer-B3单checkpoint H75**，不是推理时同时执行多个模型。
- 训练/形成历史简记：`A05 → Arm B → ACDD/C + R05/R06/R07`；对约定可训练参数离线权重平均，历史交接形式为 `theta_H75=(9*C+R05+R06+R07)/12`，冻结模块和buffer遵循原继承规则。
- **H75 checkpoint完整SHA256**：`b5eea2795d8a6d90c803a15b2ca66cf0abcf62322ef1aacd0d4d0ec82098a28a`。
- 已评分冠军ZIP历史SHA256：`c012bae1237160a0c0d5fbccd168f58facf62c03bf60ee2cc82877cb21454d30`。

已回报成功的推理链：

```text
Target RGB 1024×1024
  → RGB/255 与 ImageNet normalization
  → H75单一SegFormer-B3 checkpoint
  → D4-TTA8：rot90 {0,1,2,3} × horizontal flip {off,on}
  → 八份输出严格逆变换
  → 原生分辨率8类FP32 logits平均
  → 加固定Bstar（原生logits尺度）
  → bilinear上采样至1024×1024, align_corners=False
  → argmax得到0..7，+1得到官方1..8
  → uint8单通道PNG与3594张平铺ZIP
```

Bstar对应类别顺序为：

```python
# Background, Building, Road, Water, Barren, Vegetation, Agricultural, Vehicle
Bstar = [-0.2, 0.1, 0.0709, 0.4, 3.6, 0.4, 2.1215, -0.5]
```

**不可擅改**：旧版本偏置向量、反变换顺序、上采样顺序、argmax前后顺序；不能拿Bstar直接套M2F的query-mask probability。

### 4.2 线下短板与不可逾越的证据边界

- 旧Source统计显示H75+Bstar的Barren存在高召回、较低精度（约Precision48.16%、Recall91.66%、IoU46.15%）的假阳性风险；这不是Target真值上的逐类结论。
- Source的Zero成绩较高不能证明Target上应该删除偏置；历史Target实际恰恰表明固定Bstar更有效。

### 5.3 P1b：Saerens-EM与BBSE区别及止损

**Saerens-EM**：在假设类别先验变化而类条件特征分布稳定时，先从Source校准后验`r_i(c)`与Source先验`p_s(c)`出发，迭代估计Target先验`p_t(c)`，候选bias为`log(p_t+eps)-log(p_s+eps)`。必须使用稳定归一化并记录迭代收敛。

**BBSE（Black Box Shift Estimation）**：从Source真实GT建立条件混淆矩阵`C[pred,true]`、从Target无GT预测得到边际`q`，通过带正则的单纯形约束优化求`p_t`。对矩阵病态、负解、bootstrap大方差必须标不可靠，不能假装估到了GT先验。

共同科学约束：

- Source1399可作按图片互斥`fit699 / select350 / holdout350`及预设label-shift模拟，holdout不得反复选参。
- 新bias可考虑向原Bstar做收缩，但不得根据Target无GT统计搜索出“已知最优”的8维向量。
- 目标类预测面积变化不等于真实先验改善；Source模拟好不等于Target一定提分。

## 8. GPT Astra冲击75的方案：v1.0 → v1.1 → v1.2，详细原理与训练规格

### 8.1 为什么Astra提出新的P1方向

已发现一个长期矛盾：既有模型Source mIoU越高，未必Target越好；按老教师高置信伪标签继续训练，可能把Barren/Agricultural等系统错误继续强化；教师门槛过严时，目标有效像素覆盖甚至降到0.015709%。

Astra希望将训练新信息从**教师预测**转为**目标RGB的外观统计**：

```text
官方Source RGB（输入图像） + 官方Source GT（真实类别）
             +
官方Target3594 RGB（仅提供外观，完全没有GT）
             ↓
使用FDA在频域把Source部分低频幅度向Target donor迁移
             ↓
合成带有目标外观统计的Source RGB，GT仍然来自Source
             ↓
以H75 SegFormer-B3初始化，使用普通LoRA+原训练好的decode head微调
             ↓
比较Source donor对照A与Target donor实验B
```

**关键区别**：目标无标签图片不需要先由H75/M2F预测正确类别才能提供外观信息；学习依然使用Source官方GT监督。FDA与SAM3、DINO-B选择性KD、直接Source-only CTRL或简单8维bias搜索是不同实验机制。

理论参照：FDA（CVPR2020）低频幅度迁移；SoMA（CVPR2025，早期SoRA）是另一种可选的小奇异值参数化。文献能提供方法动机，**不能代替本赛实测、不能保证75+**。

### 8.2 Astra v1.0的三个方向

| 方向 | 定位 | 今日最终决策 |
|---|---|---|
| **P0：E02 B1官方评分** | 先从现成独立架构拿到新的Target真实反馈 | **保留最高优先级；目前用户确认未提交** |
| **P1：H75+FDA+LoRA** | 使用真实Target RGB外观迁移，Source真实GT监督 | **只完成Stage0/1，因INCONCLUSIVE关闭** |
| **P2：SoMA启发的适配器C** | 让次要奇异分量参与参数适配，减少对旧表示的破坏 | v1.1降为后置；v1.2因P1关闭而**不启动** |

对比原GPU2 M2F 60k长训，P1计划更短、可证伪、优先利用现有H75，而不是重新训练一个大型分割模型。

### 8.3 Astra v1.1为何修订、修改了哪些设计

经过交叉评审，v1.1在原方案上加入四大要求：

1. **训练前96 Source + 96 Target外观可行性诊断**：检查FDA是否使源图像的预定义外观统计接近独立Target参考，同时监控类别纹理/边界的合理性。
2. **严格匹配的A/B实验清单**：A用Source donor、B用Target donor，其他模型初始化、source图片/标签、增强、有效step、损失、采样和donor曝光尽可能相同；比较`B-A`、`B-H75`，不能只说“B比退化的A少掉一点就成功”。
3. **Zero/Bstar双轨模型诊断**：监控原生logits、类别间margin和输出类别变化，在固定Bstar部署前提下区分权重改变和偏置交互。
4. **SoMA C不进入首轮任务队列**：只有A/B1200有充分机制证据，且确实有额外GPU/截止时间预算，才另行授权C。

v1.1**仍是计划，并非全部执行**。具体历史训练计划：

| 试验 | donor来源 | 初始化 | 训练范围 |

### 8.4 FDA变换公式和参数（计划与实际Stage1所用）

对Source和donor的RGB图在空间二维做FFT，Source幅度`A_s`、相位`P_s`，donor幅度`A_t`，低频掩码`M_beta`：

```text
A_mix = A_s + lambda * M_beta * (A_t - A_s)
x_mix = real(IFFT(A_mix * exp(i*P_s)))
y_mix = y_s  # 标签沿用Source GT

beta = 0.01
lambda = 0.5
RGB的[0,1]空间先变换，然后ImageNet normalize
```

这些是**本次固定试验起点**，不等于FDA在航拍语义分割任务的最优超参数。保留相位不等于从数学上保证语义百分之百保持，因为地物类别本身也依赖色彩、地貌和纹理。

### 9.5 今日后续FDA闭线审计发现的四类技术局限（非常重要）

这些属于《FDA闭线裁决与证据限制》v1.2归档所报告的**本地代码静态审查及CPU合成数组检验**，不是新跑的真实比赛图像评估。它们修正最初执行报告，但不导致复活研究线。

**问题A：类别色彩指标会发生正负抵消。**

- `stage1_feasibility.py`先统计每类的**有符号RGB差值平均**，之后才取绝对值，公式相当于`abs(mean(delta))`，而不是`mean(abs(delta))`。
- 即使一些像素加深、另一些像素变浅，净平均可能仍接近0；因此`≤0.026`不能证明类别内每个区域的颜色变化都很小。
- 图像纹理全局比1.0008也不证明局部结构完整。

**问题B：低频掩码并未完整满足共轭对称。**

- 对1024尺寸、某个边长为10的中心低频窗口，代码使用`−5..4`的偏移，没有关于DC完整的傅里叶共轭配对。
- 静态/合成CPU检查找到掩码与配对掩码有**38个位置不同**，合成例子逆FFT虚部最大绝对值约**0.00105**。
- 当前实现直接对IFFT结果取`.real`，可掩盖非零虚部并产生额外的对称化效应。
- `lambda=0`与`donor=source`恒等测试在根本未替换频率幅度时通过，不能检出此问题。
- **不能由此证明这就是组级指标不理想的根因，也没有在官方比赛图像重跑量化其影响**。

**问题C：执行代码的GO判据比v1.1原文更严。**

- 代码设定至少两项外观指标同时满足：改善率**≥10%**、优于Source donor对照、bootstrap CI下界>0。
- 方案v1.1要求一致改善趋势与波动报告，但并未把这些条件全部写成明确10%硬阈值。该阈值应标作**执行实现中的新增判据**，不可虚称原方案预注册原文。
- 不过本次三项组级相对原Source均变远，**即使去掉10%阈值也无法据现有证据直接转成GO**。

**问题D：统计独立性与完成范围未完全满足原方案。**

- 逐图配对对齐同一Source图，**不消除Source与Target本来地物/内容不同的混杂**。
- bootstrap只是对固定参考组的96个相对改善率重采样，不含donor/reference重新抽样的不确定性，也未完全处理donor重复使用的相关性。
- 相对距离`(d0-d1)/d0`在`d0`很小时数值不稳定，亮度负向均值可能受少数离群值放大。
- 代码名叫`lowfreq`的量实际使用缩小到256后的**全径向频谱向量**，并非仅在FDA替换的低频带计算距离。
- 样本ID集合不重叠有证据，但实际按场景/近重复分组隔离、旧新样本比例匹配、冻结H75特征对照未见完整实现证据。

**归档裁决**：这些限制需要让日后研究者知道“我们没有完成一个无懈可击的FDA负结果”，但**不能用“发现了代码问题”作为比赛最后几天自动修改、重新调beta/lambda并跑满1200步的理由**。

### 9.6 为什么没有重做“每步固定少量donor”

执行Claude曾提议：把每张Source独立随机匹配一个Target donor改成每个optimizer step少量共享donor，可能降低外观统计方差。但闭线审计指出：

- 每步共享donor会改变训练样本间的相关性，**可能放大batch均值/梯度波动，不保证降低方差**。
- 少量固定donor可能降低目标3594尤其新增1794张的外观覆盖。
- 当前没有证据证明“donor随机性大”是失败根因；只改抽样方式属于新设计，需要新的授权、实验ID和对照。

因此没有执行新的donor设计，不开beta/lambda网格，不重新开始A/B训练。
