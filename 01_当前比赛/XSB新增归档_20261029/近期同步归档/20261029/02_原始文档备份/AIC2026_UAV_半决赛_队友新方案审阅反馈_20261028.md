## 2. P1：H75 + EM/BBSE——建议保留，但要保守校准

**基于：** 已评分最佳 H75 checkpoint + 原生 D4 logits + 固定 Bstar。  
**新改动：** 用 Source 有标注统计与 Target 无标注预测估计类别先验变化，通过 EM 或 BBSE 生成新的固定 8 维决策偏置；H75 权重本身不变。

### 认可之处

- 已有 **Bstar 相比 Zero bias 高约 3.02 pp** 的实证，说明类别偏置值得研究；
- EM 与 BBSE 是不同的统计估计器，分开实现、分别评估是正确的；
- 40 张数值金丝雀、Source 图像级 `699/350/350` 分割、合成 label-shift、bootstrap 和只保留少量 ZIP 的方案合理；
- 对 bias 进行去公共常数中心化、对 M2F 不直接复用 Bstar，建议保留。

### 需要强化的地方

1. **先说明假设边界。** EM/BBSE 的基本假设接近 label shift；Target 可能还存在拍摄高度、光照、地域、地貌等条件分布变化，估计出来的目标先验不一定可信。
2. **不要把 Bstar 当成“真实 Target 先验”。** Bstar 可能同时补偿分类偏置、类别混淆和训练误差。`Bstar + delta`、`(1-alpha)Bstar + alpha*b_method` 应作为**两种预注册候选**，不能在无 GT 的 Target 上选出所谓最优。
3. **防止重复补偿和类别塌缩。** 特别检查 Barren / Agricultural / Vehicle 的预测面积、每类 IoU 损失、跨图稳定性及关键混淆对。
4. **BBSE 必须检查病态性。** 如果混淆矩阵条件数过大、bootstrap 方差过大、解在不同抽样下剧烈变化，标记 `UNRELIABLE/NO_GO`，不能强行打包。
5. **保持 Source holdout 独立。** 超参仅使用 select，holdout 只作一次最终检验；Source 仿真改善不代表 Target mIoU 已提高。
6. **数值回放应优先复用已有可信原生 score 缓存，禁止重复大量 H75 推理。** 同步审计 FP16 量化对最终 argmax 的影响。

**建议放行标准：** 40 图数值回放可信；Source 模拟下相对固定 Bstar 有稳定或至少合理的收益证据；目标域预测面积无明显塌缩；类别先验估计稳定。否则保留原始 H75+Bstar，不生成无充分依据的 bias 提交包。

## 3. P2：已有 M2F E02 候选——建议尽快完成，这是最有价值的短期验证之一

**基于：** 已有 Mask2Former + Swin-L E02 B1/C0 checkpoint；**不是基于 H75 继续训练**。  
**实际任务：** 身份/协议审计 → 固定40图推理 → Source1399 检查 → Target3594 单模型推理 → ZIP QA → 人工选择上传。

### 认可之处

- 不新训练即可判断**独立架构候选**在半决赛上的真实竞争力；
- 必须区分 M2F query 分类分数与 mask 分数形成的 semantic score，不能直接把 SegFormer 的 Bstar 加到 M2F 概率图；
- 输出规范、目标域诊断和只人工提交的策略正确。

### 需要补充的核验

1. **追踪 E02 与我们此前 M2F Exp00R/Exp04 的关系。** 先判定是不是同一研究线的不同 checkpoint、短训分支或重复候选，不能只凭 B1/C0 命名判断。
2. 为 B1/C0 分别给出**权重 SHA、初始化来源、训练步数、学习率、batch、crop、EMA、推理协议和评估日志**。
3. **统一 Source 协议**并按 8 类逐项报告 IoU，尤其是 Barren / Agricultural / Vehicle；对 0.0x pp 差异不要过度解读。
4. **先单尺度 768 / 原始验证最优协议。** 不自动启用 D4-TTA8，因为我们此前 M2F 有 TTA 降分记录。
5. **把 Target3594 官方评分作为是否继续集中投入 M2F 的重要决策证据。** 在获得评分前，不得因 Source 79.x 高于 H75 不同域指标便宣称“已超过 H75”。

**建议交付：** `M2F_ASSET_AUDIT.md`、`BASELINE_IDENTITY_AND_PROTOCOL.md`、逐类 Source1399 指标、Target3594 无 GT 风险报告、单模型候选 ZIP 的 SHA 与完整 QA。

## 4. 第二GPU的 M2F 新长训——建议新增“研究价值放行门槛”

**基于：** Mask2Former + Swin-L 架构；最终指令默认由公开且合规的 Swin-L 预训练骨干**干净启动一个新的训练任务**。  
**拟改进：** Source5597 训练、768 crop、有效 batch=8、AdamW、分组学习率、BF16、EMA(decay 候选0.9999)、固定步数 checkpoint、20k/40k/60k 预算。

### 4.1 先明确：这不是“在 E02 79.56% 上继续提升”

既然默认不继承 E02 完整权重，那么新模型是**同架构的重新训练候选**。不得将 E02 Source 数值作为新模型的起点，不能把“更长训练”视为自然叠加到 E02 的增益。

### 4.2 建议在 200 步测速前增加配置差异审计

现有要求 `M2F_CONFIG_DIFF_FROM_E02.md` 很好，建议扩展为**同时与 E02、Exp00R 和 Exp04 对照**：

| 对照维度 | 必须说明的问题 |
|---|---|
| 初始化 | 是 Swin-L backbone 预训练还是 M2F 完整权重？其余 head/decoder 如何初始化？ |
| 学习率和分组倍率 | 与 E02/Exp00R 原值有何不同？是否按有效 batch 和训练长度合理调整？ |
| Scheduler/warmup | 为什么适合 20k/40k/60k，而不是直接抄 2k 或 160k 参考配方？ |
| 有效 batch 与梯度累积 | 确认 optimizer 更新次数、microbatch 数及 LR 日程的定义一致 |
| Crop 与增强 | 768 crop、随机缩放和其它增强与已做过的 Exp04 有何不同？ |
| EMA | 既有实验是否已使用？如果没有，为何预期它可能改善，而不是默认更优？ |
| 评估协议 | 新模型与旧模型是否同尺度、同列表、同映射、同计算方式？ |
| 新方案的唯一假设 | 究竟要验证“更长训练”“EMA”还是“训练配方调整”？不能混为一项可归因的改进 |

尤其需要重视：**我们的历史 Mask2Former 30k 已达到 Source1399 79.3810%，Exp04 TREAT 为 79.6019%。** 新方案若仅重复已做过的基础训练，收益不确定而成本很高。

### 4.3 对训练预算的反馈

- **保留**真实 200 optimizer steps 基准测速、前 50 预热、checkpoint 完整恢复、GPU 隔离、独立 watchdog 和截止时间安全余量。
- **不要把 200 步能跑通等同于新超参有效。** 它只能验证工程稳定性、吞吐及初步数值健康。
- **建议在自动长训 Gate 中增加 `SCIENTIFIC_JUSTIFICATION_PASS`：** 清楚记录与历史最强 M2F 的差异、研究假设、为什么值得花这批 GPU 小时、预期失败后的止损方式。
- **不要仅为了填满 GPU 时间预算而选 60k。** 20k/40k/60k 是时间可行性档位，不是精度随训练步数单调增加的保证。
- 如果时间允许而科学问题明确，建议优先保留一项变量明确的受控对照；若只能训练一个新模型，应标为**探索性候选**，不能把多处超参同时改变后的分数归因于 EMA 或长训练其中之一。
- 固定步数 EMA checkpoint 可以作为预注册正式候选，但**若文档声称 EMA 本身优于非 EMA**，必须有单独对照数据支持。

### 4.4 关于 Target 域适应

当前长训首轮不加 MIC / UDA / ClassMix / DINO 等复杂模块，我认可：这样更利于先验证训练配方。但它主要优化 Source 有监督学习，**没有针对 Target3594 域偏移的直接机制**。因此不能因为 Source 指标提高便预判半决赛线上提高。

**建议长训放行的必要信息：** 已有模型身份核验 PASS + GPU/许可/环境 PASS + 超参配置差异审计 PASS + 新实验假设明确 + 200 步工程测试 PASS + 截止时间可行。缺少前两类基础条件必须阻塞；科学性不足时建议由负责人重新确认长训价值，而不是看门狗自行决定。

## 5. P3：SAM3 辅助纠错——先证实“真实帮助”，再考虑固定 bias

**基于：** H75+Bstar。  
**拟改进：** SAM3在 Source 有 GT 上验证纠错能力；仅在专项许可和可靠性审计通过后，研究用其 Target 自动 mask 拟合固定 8 维 `B_sam`。最终推理仍为 H75 单模型 + 固定偏置。

**认可：** 按Source真值计算 `help/hurt/both_wrong`、图像级 bootstrap、先评估覆盖与误差，再考虑Target伪标签的做法是正确的。

**关键担忧：**

1. SAM3 能纠正**局部对象/边界**，不代表一个**全局 8 维 bias**可以纠正这些局部错误；全局调整可能修复少量错分，却引入大量新误报。
2. 对 Barren、Agricultural、Vegetation 等地表“stuff”类别，基于对象或文本提示的 mask 未必覆盖或映射可靠，必须记录漏检与语义映射错误。
3. Source 上 `help > hurt` 不证明 Target 上成立，SAM3/H75 一致性也不是真值。
4. 已确认官方允许使用 Test3 原始 RGB 做无监督域适应/伪标签训练，**不能自动推导 SAM3 外部权重及指定使用方式已获批准**；按原任务书继续单独保留官方书面证据。

**建议：** SAM3先定位可稳定纠错的类别/区域，作为诊断材料；若只有局部纠错而无可信全局偏置增益，不必强行生成 `H75_BSAM` ZIP。可以把更复杂的训练阶段知识蒸馏列为赛后或后续独立研究，不在本轮擅自新增任务。

## 6. P4：DINOv3-SAT / Rein-G——建议暂缓正式训练

**区分两条研究线：** v1.3 的 SAT + PMT 2000 步探针，与第二 GPU 指令里后置的 SAT/LVD + Rein-G + M2F 严格 A/B，并非同一个已验证方案。

据第二 GPU 指令引用的历史结果，DINOv3-B 教师 Source1399 为 60.0826%，选择性 KD V1 未达到覆盖要求，V2 的 Target 有效覆盖只有 0.015709%，**没有完成新学生 CONTROL/TREAT 续训**。这些结果不等于否定 DINOv3-L SAT，但也不支持直接继续在原 V1/V2 阈值上反复试。

**建议：** 关闭已失败的 DINOv3-B 选择性 KD 复跑；SAT/PMT 或 SAT/LVD+Rein-G 等后置研究在许可证、资源和独立授权具备后重新立项，并明确各自基线、唯一变量、归一化和研究目标。当前不挤占 H75 与 M2F 正式候选产出。

## 7. 两份执行计划的衔接与风险

1. **主线 GPU3 严格保护。** `ziponly-watchdog.service` 与既有 `/home/jhy/aic2026_ziponly_20261028/` 不能被第二 GPU 任务接管或覆盖；第二 GPU 仅使用经核验且授权的一张卡，UUID、进程归属与权限优先于编号猜测。
2. **不得读取其他用户私有资产。** 所有只读审计仅在当前账号已获授权的路径内进行。遇权限不足直接报告，不绕过权限、不扩权、不复制他人文件。
3. **避免重复工作。** GPU3 主线已负责 H75 原生缓存、EM/BBSE 和 M2F E02；第二 GPU 不得重复创建这些工作，除非主线负责人明确提出缺失项并同意交接。
4. **任务权限不能相互传递。** 第二 GPU 文档的条件授权只覆盖其明确列出的审计、测试和合规长训，不自动授权 SAM3 Target 监督、DINOv3 正式训练、更多 GPU 或平台提交。
5. **统一模型身份与验证口径。** 每份 ZIP 必须对应唯一权重 SHA、输入清单 SHA、推理代码/config SHA、score 语义、TTA/bias、ZIP SHA。不可把“生成成功”冒充“mIoU 提升”。
6. **线上次数有限，候选必须经过筛选。** 每天最多两次人工线上提交（据v1.3记录）；不建议低证据强度候选消耗机会，也不以在线分数进行无预注册的大范围 bias 搜索。
7. **绝不能覆盖旧最佳。** 保持 H75 原 checkpoint、Bstar、已评分 ZIP、我们的 M2F 历史 checkpoint 和指标不可变；对照指向原始权重 SHA，而不是随意重训的 CONTROL。
