## B. 当前技术事实与待核查假设

- 当前 H75 是 SegFormer-B3 权重平均形成的**一个** checkpoint，正式部署：1024 RGB → 四旋转×镜像 D4-TTA8 → 反变换、FP32平均 native 256 logits → 添加一次 Bstar `[-0.2, 0.1, 0.0709, 0.4, 3.6, 0.4, 2.1215, -0.5]`（依次 Background/Building/Road/Water/Barren/Vegetation/Agricultural/Vehicle）→ bilinear `align_corners=False` 到1024 → argmax+1 → 单通道PNG。**运行前须查实际生产源码再次核验**。
- 既有BLDA缓存是单视图 raw logits，不是完整TTA8教师，不可混为一谈。
- 原H75 checkpoint 指纹此前记录为 `b5eea2795d8a6d90c803a15b2ca66cf0abcf62322ef1aacd0d4d0ec82098a28a`；务必读取真实文件和算法确认是何种hash，不能把摘要当作文件sha256。
- SegFormer-B3典型4级通道为 64/128/320/512，1024输入对应256/128/64/32的特征空间大小，但必须对**实际H75**做forward shape断言。查看CWFA/Hook和`output_hidden_states`，排除训练期意外改变特征；不要直接复制论文MRM代码就自称复现。
- 论文MRM的语义特征重建+像素伪监督**并非**真正无教师类别标签的方案；本任务C2定义为“冻结H75特征目标的一致性学习”，**不是MRM复现**，也不能暗示有新语义真值。

## D. 第1阶段：必要功能/数值测试（先不正式训练）

建立最小、新文件形式的训练模块，**不得直接修改已有生产训练入口**。所有测试都保存命令、配置、日志和结果。

### D1. 共同实现
- Source：真实有标签图，原始CE（按H75真实代码原设置；记录ignore、插值、损失reduction）；Target：同一官方无标签测试图，仅用于图像重建，不读取/猜测其类别标签。
- 可训练共享参数默认只限stage0/stage1，冻结stage2/stage3/原decode head；新辅助头可训练。这个范围是测试假设，不代表已证实最优。明确验证冻结参数和buffers不变；冻结的后两级仍要允许CE梯度传到前两级，不能把整个encoder包进`no_grad()`。
- 训练时对stage0/stage1以及冻结网络的train/eval、BN running statistics、dropout、stochastic depth、CWFA执行实际审计；对同一源批次的C0/C1/C2行为应一致。
- 将RGB原始float [0,1]作为重建目标单独保存；输入归一化后按32×32原图像素patch做40%随机mask；mask输入置归一化空间0，需明确mask在1024坐标、目标掩码降采样到特征坐标的语义。重建目标要经历与输入相同的几何变换，但**原图未遮挡像素不得通过skip或其他路径泄漏给解码头**。
- 仅在被mask的区域计算辅助loss；float32归约、mask面积分母、finite防护。随机mask按seed复现，输出RGB可视化小样及每个真实shape。

### D2. C1：RGB-MIM（不使用教师预测）
- 从真正的 SegFormer stage1 特征接轻量训练期重建头：以实际stride为准，如stage1为128×128、128通道，可采用`Conv2d(128,3*8*8,1)+PixelShuffle(8)`得到1024×1024三通道。必须断言通道/尺寸，不符则匹配现有实际stride设计等价结构。
- `L_rgb = sum(|rgb_recon - rgb_clean| * mask_RGB) / (3*mask_RGB.sum()+eps)`。不是整图重建、不是输入与输入原样拷贝。
- 附加头只用于训练，最终必须从提交权重中删除。

### D3. C2：冻结H75特征目标（没有语义伪标签）
- 在**完全未mask**的target图上运行冻结的原H75编码器，取同一stage1特征 `F_ref`（`eval`, `no_grad`, `detach`），作为训练期表征目标，不使用类别logits、argmax、pseudo-label、Bstar。
- 对mask图运行学生编码器得到 `F_masked`，按图像mask精确/保守地映射到stage1特征网格，仅在被mask的feature token上计算`1-cosine(normalize(F_masked), normalize(F_ref))`的平均，可辅助记录feature L1但**不加入总loss**。
- 防止target特征分支误冻结；检查共享stage0/stage1梯度真实非零。冻结H75仅作特征回归参考，需明确该任务也可能复制原H75已有表征，**不等于获得更强教师纠错知识**。
- C2不是原论文MRM的伪标签训练方法；如现有stage1路径因hook或feature格式不适合，先报告并提出最小兼容适配，不得擅自更换为其他网络架构。

### D4. 单元测试与gradient audit
至少必须证明：
1. 生产基线关闭MIM后预测与原始H75逐像素一致；
2. mask比率近40%、mask对齐、shape正确，辅助头无未遮挡RGB信息泄漏；
3. C1/C2 loss在有mask时finite；mask全零时安全无损失；
4. 通过`torch.autograd.grad`分别计算`L_source`和`L_aux`对stage0与stage1代表性参数的梯度范数，检查**不是仅辅助头在学**；
5. 冻结stage2/stage3/原decode head参数和BN buffers在step前后bitwise一致；
6. 同一source batch、`lambda=0`时C1/C2的共享参数梯度与C0一致（辅助头可能无梯度，这属于预期）；
7. 对固定seed，C0/C1/C2采样、初始化和optimizer组符合配对要求；
8. 小样上重建RGB与朴素邻域插值的差异，避免“仅学到图像均值”还宣称成功。

至少做5–20个更新的smoke，发现shape/显存等问题应修复并记录，不自动转换成数千步长训。若基础功能失败，停止后续阶段。

## E. 第2阶段：小规模匹配对照（仅通过阶段1才执行）

### E1. 三组定义
- **C0（Source-only）**：H75 init + 固定源域CE短程续训；每步使用同一source batch顺序，可走目标域loader但辅助loss为零。
- **C1（RGB-MIM）**：与C0相同所有设置；唯一增加target masked-RGB重建，更新stage0/1和临时RGB头。
- **C2（Feature-consistency）**：与C0相同所有设置；唯一增加target masked-feature对齐，更新stage0/1；teacher冻结H75只给特征目标。
- 三组同随机种子、同有效更新数、同source数据顺序、同target采样顺序、同主干可训练范围、同optimizer/scheduler与相同的最终推理协议；不能用不同的batch/随机seed导致虚假结论。

### E2. 辅助loss尺度与训练预算
- `L_total=L_sourceCE+lambda_aux * L_aux`。**不要直接把RGB-L1的0.05套给feature-cosine**：不同量纲导致梯度不匹配。
- 在同一组预置的pilot batch上测量stage0/1的`||grad_source||`与`||grad_aux||`，对C1和C2分别设定**一次性固定**lambda，使初始辅助梯度/源域梯度范数比处于约0.2–0.3量级；`lambda`仅用固定pilot batch测一次并写入配置，不能根据后续目标无标签分数做网格搜索。对接近0、不稳定或梯度方向极冲突的情况要报告而不是强行除零。
- `lambda`在前50个有效更新线性ramp到目标值；建议每臂先做**300个有效更新**（非300个尝试step），保存0/100/300权重；总预算不足则在共同的短预算上终止三组，不能只让C1/C2多训练。
- 小规模抽样的target按重叠连通场景分组，先固定场景互不交叉的适应子集与无标签留出组，记录样本数；全部参赛图像依然只用于合规范围内的分析。避免“同一地面出现在训练组和留出组”造成虚假泛化信号。阶段2只是初筛，不直接扩成全量3594正式训练。

### E3. 必须统一报告（都与原H75同时比较）
- **真实GT源域**：总mIoU、八类IoU、loss与类别坍缩检查（只作安全/失败信号，不用它声称目标域提分）；将H75训练过的空间重叠图明确标注非独立验证。
- **目标域无GT**：预测类别占比、每类转移矩阵、与H75逐像素变化率、边界和小目标区域变化、源训练组与目标场景留出组的变化差异、D4一致性及适用的自监督指标（只是行为诊断，不叫精度）。
- **过拟合/漂移**：stage0/1位移范数、参数/缓冲区冻结审计、源域性能损失、辅助梯度/CE梯度范数比及夹角、C1/C2是否把大比例非背景改成背景或其他单类。
- **比较谁获益、谁受损**：明确哪些源GT像素从错→对、对→错；目标域无GT**只能写预测转换而不能写纠错**。
- 报告每臂实际训练步数、有效optimizer step数、随机种子、参数组、学习率、数据清单和可重复命令；日志附样本manifest与SHA。不要给出‘预计提升x分’。

### E4. 预设否决原则
- 任何C1/C2出现实现错误、过大的梯度冲突、冻结层或生产推理变化、显著源GT能力退化、预测单类异常膨胀：判不宜继续。
- 即使C1/C2重建loss下降、D4一致性升高，**也不得据此宣布提分**。
- 如果C1、C2在source安全与目标稳定性上均不优于C0，写出`NO-GO`，**不扩大训练，不提交**。
- 如果C1或C2显示不明显退化且具有独立、解释得通的输出变化，则写`CONDITIONAL_GO`和下一步最小线上验证建议；是否真正提升必须靠有配对条件的线上提交。
- 若功能上只有C1可行或只有C2可行，必须如实只报告那一臂，不可捏造三组齐全。
