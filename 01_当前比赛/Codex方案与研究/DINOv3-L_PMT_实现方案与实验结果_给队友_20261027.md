## 2. 方案要检验的问题

H75既有路线主要围绕B3的自训练、教师门控、校准与参数平均。此方案尝试一个能独立部署的新模型：

> 冻结通用预训练DINOv3-L提取特征，以已有分割预训练的PMT解码器学习比赛八类真实标签。

它不是把DINO当作H75的新教师，也不在推理时与H75融合。目标是检验另一套表征和区域分割解码器能否成为更强的单模型。

选择依据包括源域存在大量区域内部语义错误、冻结主干可控制训练成本、作者有公开代码与分割预训练参数。但这些只构成实验理由，**不能证明目标域问题就是主干不足，也不能承诺72分**。本实现是竞赛适配，不是完整复现论文训练配方。

## 3. 模型结构与真实前向

### 3.1 编码器

- DINOv3 ViT-L/16，通用图像LVD1689M版本，不是卫星预训练版。
- 24层，隐藏维度1024，16个注意力头，patch16，4个register token加1个CLS token。
- 主干约303M参数，全部requires_grad=False。
- 即使外层model.train()，主干仍强制eval()，前向放在no_grad内，避免主干随机位置编码增强等训练行为。
- RGB先缩放至0—1，按ImageNet mean=[0.485,0.456,0.406]、std=[0.229,0.224,0.225]归一化。
- 取第6/12/18/24层输出，分别经过主干最终LayerNorm；代码hidden_states索引为[6,12,18,24]。
- 输入1024×1024，得到64×64个空间patch。每层特征保留CLS/register，共4101个token。
- 每层特征再经过可训练的lateral SyncBatchNorm，共4层。BN按[B,1024,tokens]处理；这里沿用作者接口，当前为单GPU而非多卡同步训练。
- 解码器使用同一主干输出的RoPE位置编码。

### 3.2 PMT解码器

- 复用作者PlainMaskDecoder；6层，16头，隐藏维度与MLP intermediate维度均为1024。
- 100个可学习query。
- 四层主干特征经过各自的MLP lateral projection及残差/缩放后相加。
- query与特征拼接，形成区域掩码与类别预测。
- mask head与上采样模块输出约256×256的query mask logits。
- class head输出9维：比赛8类＋no-object。
- 6个中间输出加最终输出，共7组，训练均参与监督。
- 加载原ADE20K解码器与BN参数；150类分类头整体重置为9维，没有复用旧语义类别权重。
- 实测可训练参数：**53,704,713**。主干加解码器总量约357M；这不是“只有一个极小线性头”。

简化前向：

```python
x = (rgb_0to1 - mean) / std
with torch.no_grad():
    out = frozen_dinov3(x, output_hidden_states=True)
    features = [frozen_dinov3.norm(out.hidden_states[i])
                for i in [6, 12, 18, 24]]
    rope = frozen_dinov3.rope_embeddings(x)
features = [bn(f.transpose(1, 2)).transpose(1, 2)
            for bn, f in zip(lateral_bn, features)]
mask_logits_per_layer, class_logits_per_layer = decoder(features, rope)
```

## 6. 损失与匹配：实际实现

每张图将每个出现的语义类构成一个二值目标mask，同类不连通区域归入该类mask。将这些GT mask与100个query做Hungarian匹配。

单层总损失：

```text
L_layer = 2 × classification_CE + 5 × mask_BCE + 5 × mask_Dice
L_total = sum(L_layer for all 7 decoder outputs)
```

- class CE对所有query计算，未匹配query目标为no-object，no-object权重0.1。
- 匹配成本为2×负目标类概率＋5×点采样BCE＋5×Dice。
- 匹配时仅在GT非ignore像素中随机取12544点，不从ignore区产生负监督。
- mask loss同样排除ignore；先采3倍候选点，75%选当前匹配mask最不确定的点，其余均匀随机采样。
- mask logits用双线性采样，GT由对应原始像素位置读取；损失使用FP32。
- 单层匹配和损失独立计算；反向时再按累积步数除以4。
- 已测试：ignore位置不参与同分辨率测试中的梯度/匹配监督，反向有限，全ignore情况下loss函数返回零；实际训练数据检查排除了全ignore图。
- 此处为支持比赛ignore语义而编写的适配损失，不是声称逐字照搬作者默认loss。代码为loss.py。

## 8. 推理、结果和已经暴露的问题

### 8.1 语义分割输出

```python
mask = bilinear_resize(last_mask_logits.float(), (1024, 1024))
score = einsum("bqc,bqhw->bchw",
               softmax(last_class_logits.float(), dim=-1)[..., :8],
               sigmoid(mask))
prediction = score.argmax(dim=1)  # 内部0—7
```

必须先上采样mask logits再sigmoid和融合。当前评估为单视角，无TTA，无Bstar；没有生成正式提交ZIP。若以后打包，需另行实现/核验内部0—7到输出1—8、文件名和3594张格式。

该score不等价于H75的8通道原始logits，也不保证逐像素8类和为1；不能直接沿用H75的Bstar或将其当作已校准概率。

### 8.3 实现者必须承担的局限

1. **早期评价状态改变了结果。** 原train.py的evaluate()统一把mask概率置0，提前使用最终部署状态；对尚未退出掩码的2000步checkpoint，源域低估约2.49pp，相对于保留该checkpoint状态的比较而言。本次用相同权重补做成对评估厘清了影响。不能混挑两种协议的高分，也不能说66.04纯粹反映主干能力。
2. **修正评价状态后仍未显示足够竞争力。** 源域68.53，不能拿“更大预训练模型”作为继续押注的证明。
3. **尚未完整训练。** 目前没有4000/8000步结果，不能确定是否未收敛、是否配方不合适，也不能承诺多训会追上。
4. **H75比较并不完全匹配。** H75源域77.5311/80.4418是D4 TTA8部署评估；PMT是单视角。可以作为风险参照，不能把差值视为纯架构效应，更不能外推目标域。
5. **训练只用源域，部署校准尚未解决。** 当前半决赛H75的Zero/Bstar排名反转提醒：源域好不必线上好。PMT尚无目标域评价依据。
6. **没有逐项消融。** 预训练解码器、BN、损失采样、LR、冻结策略各自贡献未知。不能把失败责任单独归给DINO或PMT。
7. **不是完整可交付竞赛包。** 训练/验证工程已跑通，正式3594推理打包、Docker完整复现与线上成绩尚未完成。
