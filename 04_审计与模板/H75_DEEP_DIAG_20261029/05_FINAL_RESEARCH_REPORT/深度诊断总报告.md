## 摘要：一句话结论

**Source1399 无法预测 Target 表现，不是因为"验证集不够大"，而是因为它与 Target 的类别先验结构不同；而 Bstar 恰恰是在修正 Target 的先验亏缺。在 Source1399 上，Bstar 是在**重复补偿一个不存在的亏缺**，因此必然有害——这就解释了"源域涨、线上跌"的全部反转现象。**

**Bstar 的机制被完整量化：**
- **Barren bias +3.6** 把 Barren 的 recall 提高 20.5pp，但 precision 崩掉 31.0pp，预测像素 57.1M vs GT 30.4M（**过预测 1.88 倍**）

**总体：Bstar 改动 7321 万像素，纠正 2177 万、致错 4376 万，纠正/致错 = 0.497。**

### 1.3 但同一 Bstar 在 Target 上是 +3.02pp（线上事实）

H75+Bstar = **70.998665**，H75+Zero = **67.979564**（均用户报分，无平台回执快照）。

**同一个 bias 向量，在源域 −2.91pp，在目标域 +3.02pp，方向完全相反。**

## 2. 这个反转的机制解释

### 2.1 Source 与 Target 的类别先验根本不同（VERIFIED）

| 来源 | Background | Barren | Agricultural | Vegetation | 说明 |
|---|---:|---:|---:|---:|---|
| Source **train** GT（全量 5597，早前实测） | 28.14 | **1.77** | 7.14 | 28.76 | 真实标签 |
| Source **val1399** GT（本次 600 抽样） | 26.62 | **2.10** | 7.28 | 29.82 | 真实标签 |
| Target 预测（H75 raw，test3_new 抽样 300） | 28.43 | 0.74 | 8.76 | 22.15 | **预测值，非真值** |

- **Source 的 Barren 先验是 1.77~2.10%，而 H75 在 Target 上 raw 只预测 0.74%。**
- Bstar 的 Barren +3.6 正是要把这个 0.74% 抬起来。在 Target 上这是**修正真实亏缺**；在 Source 上（本来就有 2.1%），这是**无病吃药**，于是把 precision 打崩。
- Agricultural 同理：Source 7.28%，Target raw 预测 8.76%（已略高），Bstar 再 +2.12 把它推到 12% 量级 → 在两边都是过预测，但 Source 的 GT 更"密集"，所以损害在 Source 表现为 IoU 大跌，在 Target 上影响相对小。

### 2.2 关键推论

**Bstar 是一个"目标域先验补偿项"，不是"模型能力改进项"。**
它在源域失效，是**设计使然，不是缺陷**。因此：

> **任何以 Source1399 为主指标的改进，都会系统性地把 Bstar 推向"取消"的方向（Zero 在 Source 上 80.44 > Bstar 77.53），而这恰恰是 Target 上最差的方向（Zero 67.98）。**

这是本项目所有"源域涨、线上跌"的统一解释。

### 2.3 逐条对照历史反转

| 模型 | Source1399 | 线上 | 反转幅度 | 是否符合本解释 |
|---|---:|---:|---:|---|
| H75+Zero | 80.4418 | 67.979564 | −12.46 | ✅ 取消 bias → 源域最优、线上最差 |
| H75+Bstar | 77.5311 | **70.998665** | −6.53 | ✅ 保留 bias |
| CTRL@3594 | 79.1242 | 70.318575 | −8.81 | ✅ 更接近 Zero 行为 |
| T3-FULL-ST | 77.6266 | 70.990138 | −6.64 | 介于两者 |
| C1（未提交） | 78.2339 | — | — | 预期同样衰减 |

**规律：Source1399 分数越高（越接近 Zero 行为），线上越低。** 这不是巧合，而是同一条先验失配轴。

### 3.3 Source train 与 val 的类别先验差异（重要）

| 类 | train | val | 比值 |
|---|---:|---:|---:|
| Background | 27.26 | 26.62 | 0.98 |
| Barren | **1.14** | **2.10** | **1.84** |
| Agricultural | 7.25 | 7.28 | 1.00 |
| Vegetation | 29.93 | 29.82 | 1.00 |

**val 的 Barren 先验是 train 的 1.84 倍。** 原因已知：`SOURCE_AUDIT_SPLIT.json` 的 `selection_policy` 写着 *"GT-only deterministic rarity/coverage greedy"* —— **H300/val 是按稀有类覆盖率贪心构造的，因此系统性富集了 Barren 等稀有类。**

**这直接导致：在 val 上评估时，Barren 的权重被放大 1.84 倍，而 Bstar 的 Barren bias 在 val 上的"表现"与在真实 train 分布（更接近 Target）上完全不同。**

> 这是本项目验证体系最实质的一个已证实缺陷（见 Task E）。

## 4. H75 最值得修复的错误类型（Task C）

### 4.1 按目标尺寸的像素召回（raw）

| 类 | <64px | 64–256 | 256–1024 | 1024–4096 | >4096 |
|---|---:|---:|---:|---:|---:|
| Road | **8.85%** | 14.01% | 20.06% | 48.31% | 90.92% |
| Barren | **3.07%** | 11.17% | 8.18% | 15.20% | 71.05% |
| Vehicle | 12.42% | 28.54% | 61.29% | 85.56% | 91.67% |

**小目标召回极低**（<64px 的 Barren 只有 3.07%）。但注意：这些小连通域占总像素比例极小（见前次诊断：Vehicle <256px 面积占比 0.00%，Road 2.09%），**对 mIoU 的绝对贡献有限**。

### 4.2 边界带表现（距 GT 类边界 rad 像素内）

| 类 | r=2 raw→bstar | r=4 | r=8 |
|---|---|---|---|
| Background | 51.4 → **37.7** | 56.1 → 42.2 | 62.9 → 49.0 |
| Barren | 23.9 → **75.6** | 26.0 → 76.8 | 30.0 → 78.8 |
| Agricultural | 53.9 → **87.4** | 58.0 → 88.5 | 64.1 → 90.0 |
| Vehicle | 67.9 → **60.2** | 73.8 → 67.3 | 80.5 → 75.7 |

边界带上的 raw 表现普遍比全图更差（Background 51.4 vs 全图 72.5；Barren 23.9 vs 59.5），说明**边界确实是错误高发区**。但 Bstar 在边界带上的效果是"以 recall 换 precision"，不是真正的边界质量改善。

### 4.3 结论：最值得修复的错误类型

**按"可修复性 × 影响面"排序：**

1. **Barren 的 precision/recall 权衡**（源域 precision 48–79%、recall 70–91%；预测面积 1.88× GT）
   —— 这是唯一一个"两类错误同时严重且量级最大"的类别。
2. **Agricultural 的过预测**（预测 1.25× GT，precision 76–88%）
3. **Background 的欠预测**（recall 74.86–84.39，且是面积最大类 397M px）
4. 小目标召回（<64px 仅 3–12%）——**影响面小，不建议优先**
5. 边界（错误率高，但已有 D4-TTA8 部分缓解，且无独立可验证的改进手段）

## 7. 验证体系核查（Task E）

### 7.1 已证实的问题

**问题 1（VERIFIED）：Source1399 的类别先验不是训练分布，而是稀有类富集分布。**
`SOURCE_AUDIT_SPLIT.json` 明确写 `selection_policy = "GT-only deterministic rarity/coverage greedy"`。
后果：Barren 先验 val/train = **1.84**。任何在 val 上调出来的 bias 都会系统性地对 Barren 过度加权。

**问题 2（VERIFIED）：Source1399 与 Target 的不是同一"先验失配轴"。**
Source val Barren 先验 2.10%，Target raw 预测 0.74%。Bstar 补偿的是 Target 的亏缺，而 Source 无此亏缺 → 符号相反。

**问题 3（VERIFIED）：Source1399 被反复用于模型选择，已不具备独立验证能力。**
历史记录明确：H75、HPRD、ACDD 等大量候选都在 source1399 上比较过。

### 7.2 关于类别均衡抽样

任务书要求核查"EM/BBSE 实验中 Source 类别先验的计算方式，确认类别均衡抽样是否被误用为真实类别分布"。

**核查结果（VERIFIED）**：`em_bbse.py` 头部注释明确写：
```
p_s(c) from FIT GT pixel frequency (eps-smoothed)
```
即用的是 **GT 像素频率**，不是均衡抽样。**未发现把均衡抽样误用作先验的实现错误。**

但其 FIT 集来自 Source1399（同一稀有类富集分布），因此**它估出的 p_s 同样带有 1.84× 的 Barren 富集偏差**——这是继承问题，不是实现 bug。

### 7.3 禁止事项声明

本报告**没有**"根据线上已知排序反复挑选一个吻合的 Source 子集，然后宣称找到可靠验证集"。
本报告给出的是一条**机制解释（先验轴不匹配）**，它是可以被证伪的，见 §8。

## 8. 待验证假设（HYPOTHESIS）

**H1（核心）**：Source 与 Target 的排序反转，主要由"类别先验差异"解释，而非"图像外观差异"。
**可证伪预测**：如果把 Source1399 的类别先验通过重加权**对齐到 Target 的先验**后再算 mIoU，那么 Bstar 与 Zero 的排序应当反转（Bstar 变好、Zero 变差）。

**H2**：Barren/Agricultural 上 Bstar 的过预测，在 Target 上同样是过预测（只是更接近真值）。
**可证伪预测**：若 Target 真实 Barren 先验 ≈ 2%，则 Bstar 的 1.86% 预测是对的；若真实 ≈ 1%，则 Bstar 过预测。

**H3**：Source val 的 1.84× Barren 富集，使得历史上所有在 val 上做的 bias 选择都系统性高估了"压低 Barren bias"的收益。

## 9. 如果只允许做一个新实验

**做 H1 的重加权验证。**

理由：
1. **零训练、零提交、纯 CPU**，只用已有 logits 缓存与 GT。
2. **它是唯一能把"源域涨线上跌"从"现象"变成"可计算预测"的实验**——如果重加权后排序真的反转，就证明了先验轴假说，从而给出一个**可以外推到 Target 的离线指标**（这是当前最缺的东西）。
3. 若成立，后续所有候选都可以在一个**先验对齐后的离线指标**上筛选，而不是当前的裸 source1399。

**具体做法**（最小版）：
- 用 Source1399 的 logits + GT，按类别做**分层重加权**，使每类的有效像素占比 == Target 上 H75 raw 的预测占比（或某组合理估计）。
- 对 H75、H75+Zero、CTRL、T3、C1 分别计算重加权 mIoU。
- 检查重加权后的排序是否与线上排序（70.998665 / 67.979564 / 70.318575 / 70.990138）一致。

**若一致 → 找到可用验证指标；若不一致 → 推翻 H1，需另找解释（例如外观域差异为主）。**
