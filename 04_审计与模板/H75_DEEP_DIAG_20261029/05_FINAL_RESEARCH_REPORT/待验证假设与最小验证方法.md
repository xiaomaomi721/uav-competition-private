## H1（核心）：先验重加权后，源域排序应与线上排序一致

**假设**：把 Source1399 的评估按类别重加权，使每类的有效像素占比等于 Target 上 H75 raw 的预测占比，则：

- Bstar 的相对表现应当**变好**（因为它补的正是 Target 的亏缺）
- Zero 的相对表现应当**变差**

如果成立 → 得到一个**能预测 Target 排序的离线指标**；如果不成立 → 推翻先验轴解释，需另找原因（例如外观域为主）。

### 最小验证方法（零训练、零提交、纯 CPU）

```python
# 已有：
#   source1399_fp32/scores/*.npy   (1399 个 H75 raw logits, native 256)
#   manifests/source1399.csv       (含 label_path)
#   target3594_fp32/scores/*.npy   (3594 个 H75 raw logits)

步骤 1：算目标权重向量
  target_raw_pred_share[c] = 对 3594 张 target 的 argmax(z_d4) 求类别占比
  source_gt_share[c]       = 对 1399 张 source 的 GT 求类别占比
  w[c] = target_raw_pred_share[c] / source_gt_share[c]

步骤 2：重加权混淆矩阵
  对每个模型 m（H75、H75+Zero、CTRL、T3、C1）：
    正常 CM_m[c,j] 累积
    重加权 CM'_m[c,j] = CM_m[c,j] * w[c]
    mIoU' = 用 CM' 计算

步骤 3：比较排序
  正常排序  vs  重加权排序  vs  线上排序(70.998665 / 67.979564 / 70.318575 / 70.990138)
```

**成本**：约 10 分钟 CPU。不需要 GPU。

**证伪条件**：若重加权后 H75+Zero 仍然排在 H75+Bstar 之上，则 H1 不成立。
