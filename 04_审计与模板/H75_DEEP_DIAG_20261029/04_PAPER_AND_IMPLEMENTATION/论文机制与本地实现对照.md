## 1. DAFormer (CVPR 2022)

**Q1 原论文解决什么问题**：UDA 语义分割中，源域训练的模型在目标域出现"常见类偏置"与"确认偏差"——伪标签不断强化已学会的类，稀有类永不翻身。

**Q2 关键机制在哪**：
(a) **Rare Class Sampling (RCS)**：按源域类别频率倒数采样训练图，让含稀有类的图被更频繁看到；
(b) **ImageNet Feature Distance (FD)**：约束学生特征不要偏离 ImageNet 预训练特征太远，防灾难性遗忘；
(c) **warmup + 学习率策略**：先只训解码器再解冻编码器。

**Q3 训练监督信号**：源域真实 GT（CE）+ 目标域伪标签（CE，常用 teacher 生成）+ FD 正则。

**Q4 本地是否实现**：
- (a) **有代码但实际未生效**。`src/rare_crop.py` 的 `RareClassCropper(crop_size=1024, ...)` 在 1024 输入配 `crop_size=1024` 时，`max_offset_fraction=0.25` 也只会产生 0 偏移（可裁范围 = 1024−1024 = 0），**整个裁剪退化为整图**。项目历史审计 `H75_EXISTING_MECHANISMS_AUDIT.md` 已记录这一点。
- (b) **未实现**。全服务器检索 `feature_distance` / `daformer`，在项目代码中无命中。
- (c) 部分存在（warmup 在部分配置里）。

**Q5 实际差异**：RCS 的"代码存在 ≠ 运行生效"。本项目从未真正跑过稀有类重采样。

**Q6 若实现 RCS，能否改善本项目的错误？**
可能对 Barren 有帮助（当前 Barren precision 48–79%、recall 70–91% 是最大痛点）。**但风险明确**：本项目最缺的不是"更多稀有类曝光"，而是"目标域先验未知"。RCS 只能改变训练分布，不能告诉你 Target 的荒地真值占比。而且历史上 CopyPaste（另一种稀有类增强）线上 −0.311，说明"人为改变训练分布"在本赛题上反复失败。

**Q7 前提与风险**：需要重训；与"不动冠军"约束冲突；历史证据不利。

## 2. DACS (ICCV 2021)

**Q2**：**ClassMix** —— 把一个 batch 内的两张图按类别 mask 拼接，混合后的伪标签仍自洽，避免"半张图一个域"的分布断裂。

**Q3**：源 GT + 目标伪标签 + 混合一致性。

**Q4 本地实现**：**无**。全服务器检索 `classmix` / `dacs`，项目代码中无命中。

**Q5**：不适用（未实现）。

**Q6**：本项目的 CopyPaste（实例级粘贴少数类）与 ClassMix 不同——前者改动的是"实例的像素来源"，后者改动的是"整块区域的域归属"。CopyPaste 线上 **−0.311pp**，且归因为"粘贴伪影 + 破坏场景共现"。

**Q7**：ClassMix 需要目标域伪标签，而本项目伪标签质量是瓶颈（教师 test3 raw 荒地仅 0.74%）。**不建议**。

## 3. MIC (CVPR 2023)

**Q1**：目标域伪标签不可靠时，仅靠伪标签监督会学到错误。

**Q2**：**Masked Image Consistency** —— 教师看完整目标图产生伪标签，学生看**随机遮挡**的目标图，要求恢复同样的语义。这迫使模型利用**上下文**而非局部纹理，对遮挡鲁棒。

**Q3**：源 GT + 目标伪标签（教师）+ 遮挡视图一致性。

**Q4 本地实现**：**有真实实现**。`/home/jhy/rare_diag_20260915/a05_micmask_20260927/` 下有 `_mic_train.py`、`_mic_infer.py`、修复后的 `mic_infer_fixed.py` 与单元测试。

**Q5 实际差异 / 状态**：

- 旧推理包因 **1299/1300 文件错名** + **第 8 个 D4 视图逆变换错误**得到无效分 6.976285（这是工件错误，不是方法分）；
- 修复包（SHA `c9b67be9…667e41`）全链工程 PASS，**但从未评分**。

**Q6 若正确评估，能否改善本项目错误？**
MIC 对症的是"上下文不足导致的区域级误判"。本项目 66% 的错误在区域内部、灰色团 RGB 距离仅 3–15，理论上对症。**但**：MIC 需要目标域伪标签做监督，而本项目伪标签的瓶颈同样是"目标先验未知"。且本项目的 Barren 问题主要是**先验/阈值**问题，不是上下文问题。

**Q7**：最有价值的一步其实不是重训 MIC，而是**把已存在的修复包评分一次**——这是唯一"零成本、有现成产物、从未验证"的 MIC 证据。

## 4. HRDA (ECCV 2022)

**Q1**：航拍/城市场景中，小目标需要高分辨率，但高分辨率全局推理显存爆炸且丢失上下文。

**Q2**：**多分辨率裁剪训练** —— 用小裁剪提供**真实高分辨率**细节，用大裁剪（下采样）提供上下文，两者用 learned scale attention 融合。**关键：细节来自真实的像素，不是上采样。**

**Q3**：源 GT + 目标伪标签，在两种尺度上分别监督。

**Q4 本地实现**：**无**。项目有 `multi_resolution.py` 与 GLOBAL_LOCAL 方案（640 裁剪 → 1024 第二视图），但**该方案从未训练过**（只有设计文档）。

**Q5**：不适用。

**Q6 本轮的关键区别（必须说清）**：
本轮做的"512 裁剪 → 1024 上采样 → 推理 → 回填"是**伪高分辨率**：512 个真实像素被插值成 1024，**没有新增任何信息**，反而缩小了上下文。实测三档规则全部为负（−2.17 ~ −8.88pp），纠正/致错比 0.20–0.60。

**HRDA 用的是真实高分辨率裁剪，本轮用的是上采样，两者本质不同。本轮结果不构成对 HRDA 的否定。**

**Q7**：若要在本项目实现真 HRDA，需要 2048 分辨率原图或更细的原始数据——本赛题原图就是 1024×1024，**不存在更高分辨率的真实像素**。所以 HRDA 的核心前提在本赛题**不成立**。

## 5. Label Shift / BBSE

**Q1**：训练与测试的**类别先验**不同（p(y) 变了），但 p(x|y) 不变。

**Q2**：用源域混淆矩阵 C 与目标预测边际 μ，解 `Cᵀ p_t = μ` 反解目标先验，再据此做 logit 调整。

**Q3**：只需源域有 GT + 目标无标签预测。

**Q4 本地实现**：**有**（`aic2026_ziponly_20261028/code/em_bbse.py`，Saerens-EM + BBSE + alpha 收缩，fit/select/holdout 三段划分）。

**Q5 实际结果**：
- 7 种模拟偏移下，BBSE 平均比固定 Bstar 高 **+1.3778pp**；
- 但 `G-B5_magnitude` 门槛 **失败**（max_abs_delta = 1.438 超阈值）；
- 未产出线上候选。

**Q6 与本报告的关系（最重要）**：
本报告的诊断**独立地指向同一结论**——本项目"源域涨线上跌"的根因就是 **label shift**（Source val 的 Barren 先验 2.10% vs Target raw 0.74%）。
**所以 Label Shift 这条线是本项目唯一有理论依据、且已被两条独立证据支持的方向。**

**Q7 风险**：BBSE 依赖 "p(x|y) 不变" 假设，而本项目 Target 还更暗更糊（§B），说明 p(x|y) 也部分变了。所以 BBSE 只能补先验部分，不能补外观部分。
