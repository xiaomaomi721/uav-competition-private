## 零、两个必须先说清的错误（都是我的）

### 错误 1：我说"S 上界 ≈ 1.0，空间饱和"——**错在一个很基础的地方**

**GPT 的质疑成立（S 确实超过 1），但我给出的解释也是错的。**

实测：pipeline 产出的 S 在 TTA8 均值后**确实超过 1**，全库最大
**1.2902371883392334**（val 缓存 1399 张），>1.0 的像素有 **2,369,100** 个。

我最初的论证是 `H = Σ_q softmax_q · sigmoid ≤ Σ_q softmax_q ≤ 1`。
进一步拆测后**这个论证的根本就是错的**：

```
Σ_q Σ_{c<8} softmax(class_logits[q])[c]  =  2.9954      ← 在异常点上
Σ_q Σ_{c<9} softmax(class_logits[q])[c]  =  1.0000      ← 这才是 1
```

**每个 query 的 9 路 softmax 各自归一到 1，100 个 query 叠加，
上界是 Q = 100，不是 1。** 我把"单 query 的类别归一化"错当成了"跨 query 的求和上界"。

所以：
- **S ∈ [0, ~3] 是正常值域**，S > 1 只表示有若干个 query 同时把该像素判给同一类。
- **没有 attention mask 失效，没有训练分布外推，没有 query 互斥问题。**
- 我为此做的那次 SDP 内核实验（cudnn / flash / mem-efficient / pure math 四种）
  结果是 `S.max` 全为 1.9948 —— **证伪了一个本来就不存在的假设**。
  该实验唯一的价值是顺带确认了内核选择不影响输出。

**净结论**：关于"空间饱和 / 归一化失效"的整条解释链**全部作废**，
margin 的数字继续有效，但**不能再用"上界 1"去解读它的量级**。

**后果（这才是重点）**：无。这一条不影响 E 表、身份核对、margin 分布数值的任何一项，
也不影响第六节的任何战略判断。它只删掉了一个错误解释和一个错误候选。

### 错误 2：我说 F−C 的符号能验证内部自洽

**GPT 正确，撤回。** 融合确实是线性的，但后面还有 argmax → 混淆矩阵 → IoU，全是非线性的。
score 域的差值方向推不出 mIoU 差值的符号。六个包全负的结论不受影响，但那条不能当验证证据。

## 一、身份核对：PASS（这是 GPT 要的第一件事）

`identity_check_score_tensor.py`，12 图，GPU2，对**已提交的 ZIP** 逐字节比对：

| 检查 | 结果 |
|---|---|
| `S = forward_views(model, px, 1).mean(dim=0, dtype=torch.float32)` 的 shape/dtype | `[8,1024,1024]` / `torch.float32` |
| S 全域 min / max | `0.000000008` / `0.999997258` |
| `argmax(S)` vs 已知 ZERO 参考 PNG | **0 / 12582912 差异** |
| **`argmax(S + [0,0.2×7])` vs 已提交 `02_M2F56_FG_POS_020_TTA8.zip`** | **0 / 12582912 差异 ← 身份成立** |
| 对照：bias 加在均值之前 `(views+b).mean()` | **190699 差异**（说明该测试灵敏度很高） |
| 判别力：`argmax(log(S+1e-6))` vs `argmax(S)` | 0 差异 |

**结论**：`measure_final_margin.py` 测的**就是**线上包取 argmax 的那个 tensor。
`0..0.999997` 与 `[0,1]` 的说法是对的；1.2902 是 **val 缓存**的对象。
两者口径不同、都对，但**不是同一批图**。

**副作用（重要）**：对照实验里 bias 加在均值**之前**会改变 19 万像素（1.5%），
所以"bias 加在均值之后"这件事是**被实测钉住的**，不是约定。

## 三、E 表说明了什么

### 1. M2F 的翻转几乎全部是 Background→前景

| 向量 | 翻转量 | 方向 | 最大的几个转移 |
|---|---:|---|---|
| F (+0.05×7) | 0.299% | 背景流失 | BG→Veg 25.8% / BG→Bldg 23.0% / BG→Agri 20.0% / BG→Road 16.2% |
| H (+0.10×7) | 0.581% | 背景流失 | **同样四个，占比几乎一模一样** |
| FG_POS_020 (+0.20×7) | 1.141% | 背景流失 | **同样四个，占比几乎一模一样** |

**+0.05 → +0.10 → +0.20 是同一个方向被放大，只是量不同。**
flip% 近似正比于 span（0.2985 / 0.5808 / 1.1409 ≈ 1 : 1.95 : 3.82，而 span 比是 1 : 2 : 4），
E 却从 0.156 掉到 0.133 再掉到 0.085。

**边际收益递减的机制是**：每多翻一个像素，它落在"该翻"区域的条件概率在下降。
**不是撞到了某个硬边界。**

### 2. 负向很糟，而且是结构性的

E(−0.05) = **−0.118**，G(−0.10) = **−0.130**。
**负向是背景→前景的逆过程，0% 的翻转是 BG→前景**（即全部是前景→背景）。
每一单位翻转都是净损失。

这**推翻**了台账里"压低背景得分的方向有效"的含义。准确表述是：
**在 ZERO 之上把 7 个前景整体抬高有效；整体压低就是等量的反向亏损。**
所谓"压低背景"其实是"抬高前景"的同一件事（背景被固定为 0）。

### 3. Stage59 的翻转是"修召回"，M2F 的翻转是"重新分配"

| | Stage59 FIXED8D | M2F FG_POS_020 |
|---|---|---|
| flip% | 5.4084 | 1.1409 |
| 构成 | **Background→前景 84%** | Background→前景 100% |
| 其中 | BG→Barren 17.7%（Barren +3.6 是大头）、BG→Agri 44.5%、BG→Veg 9.8% | BG→Veg 25.8%、BG→Bldg 23.3%、BG→Agri 20.2%、BG→Road 15.9% |
| E | **0.2382** | 0.0848 |

**注意 M2F 的四个主要转移类别，和它的类别先验完全一致**——
它并不是在修某个薄弱类，而是在按先验比例把背景像素"分给"前景。

### 4. E 的排序

```
Stage59 FIXED8D        0.2382   <- 唯一有干净平台对照的旧算子
M2F F (+0.05)          0.1561
M2F H (+0.10)          0.1326
M2F FG_POS_020         0.0848   <- M2F 最佳，但单位翻转效率最差的一档
M2F C (2x joint)       0.0231
M2F A (joint_local)    0.0411
M2F B (joint_1d)       0.0380
M2F D (反向)          -0.0806
M2F E (-0.05)         -0.1178
M2F G (-0.10)         -0.1304
```

**M2F 最优点（+0.20）恰好落在它自己效率曲线的最低点。**
说明 **+0.20 不是"更好的偏置"，只是"扫得更远"**。

对 pre-softmax 六包的直接含义：
它们的翻转量比 final-score 更小（实测 0.002–0.005%，即约 100 倍小）。
若 E 相近，则 Δ ≈ 0.0002–0.0006pp —— **会被平台打分噪声淹没**。
所以预注册判据里"≤0.6853 就保留 final-score"这一档，**大概率就是结局**。
这不改变要提交的决定（信息免费），但**不要对 pre-softmax 抱有期望**。

## 四、margin CDF（GPT 的 ①）

M2F56 R1b final semantic score，val 1399 张，14.67 亿像素：

| 分位 | p1 | p5 | p10 | p25 | p50 | p75 | p90 | p95 | p99 |
|---|---:|---:|---:|---:|---:|---:|---:|---:|---:|
| margin | 0.0358 | 0.2612 | 0.5326 | 0.9435 | **0.9875** | 0.9912 | 0.9935 | 0.9943 | 0.9949 |

| margin < | 0.01 | 0.05 | 0.10 | 0.15 | 0.20 | 0.25 | 0.30 |
|---|---:|---:|---:|---:|---:|---:|---:|
| 像素占比 | 0.54% | 1.32% | 2.20% | 3.05% | 3.97% | 4.88% | 5.6% |

**读法**：median 0.9875 极高，但**尾部很厚**——
margin < 0.20 的像素有 **3.97%**，而 +0.20 恰好只能翻动其中一部分。
实测 FG_POS_020 翻了 1.14%，落在"margin < 0.20 的 3.97%"之内，量级自洽。

**但必须标注一个口径问题**：S 的值域是 **[0, ~3]**（见第零节），不是 [0,1]。
所以"margin 0.9875 接近上界 1"这句话**没有意义**——
margin 的实际上界是**该像素 top1 通道的 S 值**，逐像素不同。
median margin 落在 0.987 附近，反映的是 **S 的众数区间在 1 附近**，
不是"接近饱和"。

**正确的读法只有相对的那一句**：+0.20 的相对位移是 median margin 的 20%，
能翻动 margin < 0.20 的尾部 3.97% 中的一部分（实测 1.14%）。
**绝对量级的解释已作废。**

**注意与 test1 的差别**：身份核对里 test1（12 图）的 S 全域 max 是 0.999997，
val 缓存 max 是 1.2902。两者都是同一对象的正常取值，
差异来自图像内容与 query 激活数量，**不构成异常**。
**val 的 margin 分布能否外推到 test1 仍未验证**，这一条保持标记。
