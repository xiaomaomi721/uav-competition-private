## 一、① 硬移植测量（权重绑定 + 3 包）

### 权重绑定（逐项可验证）

| 组件 | 来源 | 绑定 |
|---|---|---|
| **encoder** | M2F56 Run1b step56000 | `formal_run1b/scores/score_iter56000.pt` → key `model`；SHA256 `707a582df4cf5a22227ed73db9cf4bdad7e1689f72ae9f99f71fd09e22629272`；`data_iteration == 56000` |
| **decode head** | Stage23 best56000 | `stage23_runs/stage23_w1_exp23_b3_1024_cwfa_ce_formal_seed42/best_miou.pt` → key `model_state_dict` 中 `decode_head.*`（**16 个张量**，含 `linear_projections.{0,1,2,3}` + classifier）；SHA256 `d3740b4ef73fbb3ac57ddeedc3547ce4ce1ba31442dc7c70e1fe96b1fab3e228` |
| **config** | Stage23 正式 | `.../stage23_w1_exp23.../config.yaml`；SHA256 `68cf3a98b7bb17dc564fbbb31dced103543e86bd9e01b967c161c37f1120995c` |

**接口验证（前推前必须通过）**：`segformer` 的 4 个 stage 输出通道必须等于 decode head 的
`linear_projections.{0,1,2,3}.proj.weight` 的 `in_features`。两者都是 MiT-B3，预期为 (64, 128, 320, 512)。
**不匹配则立即停止，不产出任何包。**

### 协议

D4-TTA8、FP32、autocast 关闭、`forward_views` 逐视图 → 逆旋转/镜像 → 双线性到 1024 → FP32 均值 → +bias → argmax+1。
与已提交包完全同协议（与 `identity_check_score_tensor.py` 验证过的路径一致）。

### 3 个包（一次 forward，bias 后加，零额外 GPU 成本）

| # | tag | bias 向量（8 维，train class 序） |
|---|---|---|
| 1 | `BRIDGE_ZERO` | `[0, 0, 0, 0, 0, 0, 0, 0]` |
| 2 | `BRIDGE_CHAMPION` | `[-0.2, 0.1, 0.0709, 0.7, 3.6, 0.4, 3.3215, -0.5]` |
| 3 | `BRIDGE_RECORD13` | `[-0.2, 0.1, 0.0709, 0.7, 3.6, 0.4, **2.9215**, -0.5]`（农田 3.3215→2.9215） |

**第 3 个 = 13 号包（0.693096）的确切算子**，已从 `提交清单.json` 核对。

### 输出两个量

```
C = mIoU(BRIDGE_ZERO)
P = max(mIoU(#2), mIoU(#3)) − C
```

### 参照锚点

| 本体 | P |
|---|---:|
| Stage23 B | **+1.4789 / +1.5073** |
| s62 | +0.5637 |
| M2F56 final-score | +0.0967 |

### 判据：①**只**决定 ③ 的 anchor，不决定 ③ 做不做

| 观测 | 决策 |
|---|---|
| `P ≥ 1.0pp` | calibration 高度依赖 **Stage23 head** → **③ 走 M2F-anchor** |
| `0.4 ≤ P < 1.0` | 未分辨 → **仍走 Stage23-anchor**（优先保护脆弱资产），并记录①未settle |
| `P < 0.4pp` | calibration 依赖 **encoder/training state** → **③ 走 Stage23-anchor**（首选） |

**C 作为辅助读数**：`C ≈ 0.684` 表示 M2F core 能穿过外来 head；`C < 0.680` 表示穿不过，
这本身也支持 Stage23-anchor（M2F-anchor = 同一个 splice + 训练）。

## 二、③ 首个结构实验：**只选 Stage23-anchor**

### 为什么选它（理由，非偏好）

1. **Stage23 的 calibration geometry 是历史上更脆弱的资产**——s62/M2F 两条线都显示它会消失。
   Stage23-anchor **从不摧毁它**；M2F-anchor 必须先摧毁再指望学回来。
2. **起点是已验证的良好工作点**（0.678023 / P=+1.4789）；M2F-anchor 的起点质量未知，且等于 ① 的 splice。
3. **失败模式更可读**：Stage23-anchor 失败 = "mask 监督压不住 CE"，是可解释的；
   M2F-anchor 失败可能只是 splice 本身坏了，归因不清。

**①如果给出 `P ≥ 1.0pp`，这条推荐应被推翻**——这正是 ① 先跑的意义。

### 两阶段设计

**阶段 3-0：辅助头再锚定（head-only，≈200–500 步，≤5 分钟）**
M2F aux head 是在 M2F56 特征上训的，直接冻在 Stage23 特征上会输出垃圾，aux loss 无意义。
所以先只用 Stage23 encoder 特征训练 aux head 若干步，使其输出非退化。
**验证**：aux loss 下降且 mask 覆盖率非退化；**不产出任何包**。

**阶段 3-1：主训练（唯一产物阶段）**

| 组件 | 初始化 | 状态 | LR |
|---|---|---|---|
| encoder | **Stage23 best56000** | **可训练** | `1e-5` |
| primary head（SegFormer decode head） | Stage23 best56000 | **冻结** | — |
| M2F aux head | M2F56（先经 3-0 再锚定） | **冻结** | — |

**为什么两个 head 都冻结**：目标是"只加入 mask 监督"这一个变量，
其余尽量贴近已知良好的 Stage23。冻结 primary head 后 CE 梯度只进 encoder，
冻结 aux head 后 mask 梯度也只进 encoder —— **两个监督都在塑形 encoder，没有旁路吸收**。
（这正好回答了"aux head 是否 frozen"：是，但必须先做 3-0 再锚定，否则信号无意义。）

**副作用（如实说明）**：冻结 head + 移动 encoder，终点形态 = **"训练出来的 ①"**。
这使 ① 与 ③A 互为对照，是优点；但也意味着 head 的容量未被利用，可能限制上限。

### 损失

```
L = CE(primary_head(enc(x)), y) + λ · L_mask(m2f_aux_head(enc(x)))
```

`L_mask` = M2F 的 set/mask 损失（分类 + mask BCE + Dice，含匈牙利匹配），沿用 `b3_m2f_head/loss.py` 已有实现。

**λ 的取值依据（须说清是约定而非调优）**：
本项目历史上"主损失 + 0.5·辅助损失"是既定约定（SEMEDA：`main_loss + 0.5·embedding_loss`）。
**取 λ = 0.5 作为唯一首发值**，不做 sweep。理由：λ 必须足够大以移动 encoder，
又不至于压过 CE；但**这没有实验依据，首发结果正是用来判断这个量级的**。

### 步数 / 检查点 / 包数

| 项 | 值 |
|---|---|
| 步数 | **4000 optimizer steps** |
| 检查点 | 2000、4000 |
| 包数 | **4 个**：两个 checkpoint 各出 `ZERO` + `RECORD13` |

### 总 GPU 成本（按 s62 实测 1.533 s/optimizer-step）

| 项 | 估计 |
|---|---|
| ① 前推 + 打包 | ≈ 25–30 分钟 |
| 3-0 再锚定 | ≤ 5 分钟 |
| 3-1 训练 4000 步 | ≈ 1.7 小时 |
| 2 × TTA8 前推 + 打包 | ≈ 50–60 分钟 |
| **合计** | **≈ 3 小时** |

（首次运行前用 smoke 实测步时，再校正。）

### Stop rule

| 观测（4000 步） | 动作 |
|---|---|
| `ZERO ≥ 0.684133`（≥ M2F）**且** `P ≥ 1.0pp` | **成立**：core 与 calibration 已解耦 → 继续加步/调 λ |
| `ZERO` 上升 **但** `P < 0.5pp` | **失败**：mask 监督摧毁了 calibration → 停止，记录为反证 |
| `ZERO` 下降 | **失败**：λ 过大或 freeze 过严 → 停止，不加步不扫 λ |
| 中间态 | 只再跑**一个** λ 值（单一对照），不扫 |

**不做大 sweep。** 每一档都要线上结果才推进。
