# 方法集成决策清单（合规版：单模型内部多方法融合）

> 用途：线上分一回来，照这张表机械判断"该集哪个、不该集哪个"，不用重新想。
> 前提：赛题规则第3条**只禁止多模型 ensemble**，方法集成（单模型内多方法）**合规**。当前最强 69.276 本身就是 CWFA+旋转TTA8+校准 的三方法集成。
> 更新：2026-08-29

---

## 一、核心规则（历史铁律，先背）

1. **同类方法不可叠**：CWFA + no-decay 三合一 = 66.196（比基线低 0.54），因为两者都是"正则"，剂量翻倍=过正则=欠拟合。**MixStyle 和 CWFA 也是同类（域泛化正则），不可叠。**
2. **异类/互补方法可叠**：机制不同的方法理论上 1+1>1。
3. **但必须先测单方法正负**：历史"训练期技巧大多拖后腿"，只有单用为正的方法才值得集。**集成的前提 = 两个单方法都线上正收益。**
4. **校准+TTA 已到顶**：这层（测试期先验）已经榨干，集成只在"训练期方法"之间做。

## 二、方法按机制分类（决定能否叠）

| 机制 | 方法 | 单用状态 |
|---|---|---|
| ① 外部知识注入 | 蒸馏 DINOv2(Exp31) / SAM3 | 待判（Exp31 线上） |
| ② 域泛化正则（**同类互斥，只能取一**） | CWFA ✅+0.632 / MixStyle(Exp34) / no-decay ✅+0.673 | CWFA/no-decay 已在 B3 证正，MixStyle 待判 |
| ③ 少数类数据增广 | CopyPaste(Exp33) | 待判（Exp33 线上） |
| ④ 测试期先验 | 校准 / 旋转TTA | **已到顶**（+1.9 榨干） |
| ⑤ 参数调对 | 低lr+大drop_path(Exp35) | 待判（B4，非"方法"是"调参"） |

**关键**：①②③ 机制互不相同，理论上可各取一个 + ④ 全上，集进同一模型。这是正确的方法集成。三合一的错是"②里取两个叠一起"。

---

## 三、集成组合清单（按突破概率排序，带触发条件）

> 记法：**"X + Y"能否启动 = X 单用正 且 Y 单用正 且 X、Y 机制不同类**。

### 组合1：蒸馏(①) + MixStyle(②) + 校准TTA(④)  ★★★ 最可能突破
- **为什么**：蒸馏补"灰色团纹理表示"（真难点），MixStyle 补"域漂移"，机制完全不重叠。
- **触发条件（缺一不可）**：
  - [ ] Exp31 蒸馏线上 **> 67.37**（B3+CWFA 标准版，即蒸馏正收益）
  - [ ] Exp34 MixStyle 线上 **> 67.37**（MixStyle 正收益）
- **启动动作**：新建单 config，同时开 distill + mixstyle（两者代码都已就绪，各自独立挂载，可同开），训完套校准+TTA。
- **风险**：蒸馏和 MixStyle 都是训练期技巧，历史上这类易负；但二者机制互补是唯一希望点。

### 组合2：蒸馏(①) + CopyPaste(③) + 校准TTA(④)  ★★☆
- **为什么**：蒸馏攻"分不清"，CopyPaste 攻"样本少"，一个补表示一个补数据。
- **触发条件**：
  - [ ] Exp31 蒸馏正收益（>67.37）
  - [ ] Exp33 CopyPaste 正收益（>67.37）
- **启动动作**：单 config 开 distill + copy_paste。
- **注意**：CopyPaste 是"输入增广"，历史增广全负，需 Exp33 真正确认正收益才集。

### 组合3：MixStyle(②) + CopyPaste(③) + 校准TTA(④)  ★★☆
- **为什么**：域泛化 + 少数类增广，机制不同。
- **触发条件**：Exp34 正 且 Exp33 正。
- **启动动作**：单 config 开 mixstyle + copy_paste。

### 组合4（不推荐）：任何"②类里取两个" ❌
- CWFA+no-decay 已证崩。MixStyle+CWFA、MixStyle+no-decay 同理**禁止**。
- **永远只从②里选一个**。

## 四、优先级顺序（时间/算力有限时的决策树）

```
等 5 条线线上分 → 按下面顺序判断：

1. Exp31 蒸馏正 且 Exp34 MixStyle 正 → 立刻上"组合1"（最可能突破 69.28）
2. 只有 Exp31 正 → 上"蒸馏 + 校准TTA"，并考虑把教师从 DINOv2 换 SAM3 走深
3. 只有 Exp34 正 → 上"MixStyle + 校准TTA"（即 CWFA 强化版，稳扎稳打）
4. Exp33 CopyPaste 正 → 无论前两者，都可作为"③"叠加进组合1/2
5. 全负 → 说明"训练期技巧"在本赛题确实死路，回退到"只靠测试期先验"（校准/TTA 已到顶 69.276），
   唯一剩的合规外部知识路 = 蒸馏换更强教师（SAM3）重试
```

## 五、给每个待判方法定的"正收益阈值"（很重要）

为什么用 67.37 当阈值：**B3+CWFA 标准版 = 67.37**，是所有 B3 训练期方法的对照基准。任何新方法标准版若 **≤67.37**，说明它没比现有 CWFA 强，不值得集成。

| 待判线 | 标准版对照 | 正收益阈值 |
|---|---|---|
| Exp31 蒸馏 | 67.37 (B3+CWFA) | **>67.37** |
| Exp34 MixStyle | 67.37 (B3+CWFA) | **>67.37** |
| Exp33 CopyPaste | 67.37 (B3+CWFA) | **>67.37** |
| Exp35 B4低lr | 66.95 (B4纯CE) | **>66.95**（B4 自己的基线） |

## 六、诚实自评（结论）

1. **方法集成是合规且正确的突破方向**，但现在的正确动作**不是急着集**，而是**等单方法线上分筛出正收益者**。
2. 最可能突破的组合是 **蒸馏 + MixStyle + 校准TTA**（组合1），因为蒸馏是唯一"外部知识"、MixStyle 是已验证 CWFA 的强化、机制互补。
3. **别在结果出来前赌集成**——历史告诉我们训练期技巧多为负，赌错了浪费 15h 训练 + 提交名额。
4. 唯一值得提前做的准备：**确认蒸馏和 MixStyle 的代码能在同一 config 里同时开启且不冲突**（两者都通过 decode_head forward hook 挂载，需验证不打架）。这个可以现在查，不占 GPU。

## 七、共存验证结论（2026-08-29 已实测）

**蒸馏 + MixStyle 可共存，代码零冲突**，已跑通 `SMOKE_COEXIST_PASS`（forward/loss/backward/step 全链路 OK）。

- 挂载点不同：蒸馏在 trainer 训练循环显式调 `model(output_hidden_states=True)` 拿 stage4 特征；MixStyle 是 `decode_head.register_forward_pre_hook`，在 decode_head 前扰动 `hidden_states[-1]`。
- config key 独立：`distill:{enabled,teacher_path,lambda,start_step}` 与 `mixstyle:{enabled,probability,alpha}`。
- 子模块独立：`_uavseg_distill_proj` vs `_uavseg_mixstyle`，互不覆盖。
- **启动组合1 只需在 config 里同时写两个块**，验证脚本 `deploy_exp18/smoke_distill_mixstyle.py` + config `configs/stage35_smoke/smoke_distill_mixstyle.yaml` 已就位。

→ **组合1（蒸馏+MixStyle+校准TTA）已做到"线上分一回来立刻零等待启动"**，唯一前提仍是 Exp31 正 且 Exp34 正。
