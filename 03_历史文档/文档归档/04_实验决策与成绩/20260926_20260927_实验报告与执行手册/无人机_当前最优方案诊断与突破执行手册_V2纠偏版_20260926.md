# 0. 本版与旧手册的关键区别

旧手册把 ETKD 设为唯一突破主线。P1 已给出以下结果：

| 指标 | P1 结果 | 判定 |
|---|---:|---|
| candidate teacher KL | 0.011492 | — |
| D1 teacher KL | 0.011324 | — |
| KL reduction | **−1.48%** | 未学到 teacher |
| candidate vs teacher flip | 1.05% | 比原始 D1→teacher 约0.872%更远 |
| candidate vs D1 flip | 1.15% | 总量可控但包含新增漂移 |
| per-image max flip vs D1 | **34.2%** | 局部过冲 |
| H300 mIoU delta | −0.039pp | 未发生明显 source collapse |
| Background share delta | −0.45pp | 接近风险边界 |

这说明：

1. 移除 `strong_photo` 是正确修正，KL 恶化从 v1 的约14.4%收窄到1.48%；
2. 但当前 `source CE + 全像素 teacher KL + 单随机D4 student` 仍不能稳定学习 teacher；
3. 问题不是单纯 source 崩坏，而是 student 在 teacher 没要求变化的区域产生了 **novel changes**；
4. 继续把 ETKD 当主要突破路线不合理，因为它追逐的 teacher 相对 D1 只高约0.027621pp；
5. 过去还存在 logit插值/权重插值混淆、旧 evaluator 标签 bug、source holdout 错当线上排序器、旧 Vehicle 诊断不自洽等判断依据问题。

因此，本版把主线改为：

```text
修正事实与评估依据
→ 冻结 P1 FAIL，不再救当前 ETKD
→ 用 D1 真正 parent 构造单-checkpoint权重投影
→ 用 teacher 行为做无GT函数空间投影
→ 完成 D1 机制消融
→ 设计“更干净、受约束、不过冲”的 D1-v2
→ 只有低维投影和 D1-v2都失败后，才考虑 Delta-KD
```

本版核心原则：

> 不再让高维训练盲目模仿一个微弱 ensemble 效果；先把已有线上有效方向投影为单 checkpoint，再研究 D1 为什么有效以及如何减少过冲。

# 2. 问题根因：方法和判断依据分别错在哪里

## 2.1 正确的大方向

D1 已被线上证明有效，因此以下方向没有错：

```text
利用官方 test2 无标签图像
+ 高可靠伪监督
+ source GT 保持
+ 主要适配 stage2/stage3
+ 最终单 checkpoint
```

## 2.2 选错的下一目标

旧主线试图把只比 D1 高约0.027621pp的 logit平均 teacher 压入单模型。

问题：

1. 该收益很小；
2. 可能主要来自输出平均降低方差，而不是新语义知识；
3. 没有 test2 GT，不知道 teacher 与 D1 不同的约0.87%像素中哪些真正带来提升；
4. 全像素 KL 模仿的是 teacher 全部分布，不是“真正贡献线上增益的像素”；
5. source CE 与 teacher KL 可能冲突；
6. 高维 AdamW 会在 D1/teacher原本一致的区域产生 novel changes。

所以 ETKD 更适合“合规压缩研究”，不应再作为唯一提分主线。

## 2.3 明确错误的判断依据

### 错误 A：logit alpha 和 weight alpha 混用

线上 `70.763755` 是 logit融合；旧本地 alpha sweep 是权重插值。两者不是同一个模型。

### 错误 B：旧 alpha evaluator 的 GT bug

旧代码：

```python
if gt.max() > 7:
    gt = gt - 1
```

GT含 ignore=255 时会错误减1。旧 `interp_results.json` 不能用于模型选择。

### 错误 C：H300/R1099 被当作线上排序器

已有反例：

- GTRUST 本地强正、线上强负；
- D1 H300下降、线上上升；
- SWA 本地微正、线上负。

以后 H300/R1099 只防崩，不预测0.02pp级线上差异。

### 错误 D：旧 error analysis 指标冲突

Vehicle IoU 0.293 与其他评估0.76–0.82不相容。在 canonical 重算前，不得用旧报告选择 prototype/contrastive。

### 错误 E：晋级门和研究门混在一起

`P1不满足+5% KL`只能说明它不能晋级，不自动证明所有训练长度下永远无效。但本次还有 teacher距离恶化、极端flip、Background漂移，因此具体P1配方仍应判失败。

后续每个实验必须区分：

- **安全硬门**：失败立即停；
- **晋级门**：失败不得进入正式/提交；
- **诊断预算**：可以另立只读/诊断任务采集有限轨迹，但不能救活候选。

# 6. Phase 2：构造单-checkpoint A05_WEIGHT

这是当前最高优先级实验。

## 6.1 为什么优先

A05_LOGIT_TEACHER为：

```text
0.5*f(parent) + 0.5*f(D1)
```

构造：

```text
theta_A05 = parent + 0.5*(D1-parent)
```

由于D1参数变化小，一阶近似下权重中点可能天然接近logit中点。与ETKD相比，它：

- 无训练噪声；
- 不受source CE/teacher KL冲突；
- 不会任意离开parent→D1方向；
- 最终是单checkpoint；
- 成本低；
- 过去没有被正确评估，因为旧alpha evaluator有bug且可能用了错误parent。

## 6.2 新脚本

```text
frozen_code/build_weight_projection.py
```

CLI：

```bash
python build_weight_projection.py \
  --parent <D1真实parent> \
  --target <D1 checkpoint> \
  --alpha 0.5 \
  --output <new-path> \
  --manifest <json>
```

## 6.3 tensor处理规则

对所有浮点参数：

```python
out[k] = parent[k].float() + alpha * (d1[k].float() - parent[k].float())
```

保持原目标dtype前，必须先在FP32完成计算。

对整数tensor和buffers：

- parent与D1相同：保留parent；
- parent与D1不同：立即FAIL并人工审计；
- 禁止对整数、计数器、索引做算术平均。

必须验证：

- key集合完全相同；
- shape完全相同；
- strict load；
- stage0/1应与parent bitwise相同；
- `FULL_D1 alpha=1.0` control的canonical state hash必须等于原D1；
- `alpha=0.0` control必须等于parent。

输出：

```text
03_weight_projection/A05_WEIGHT_SINGLE_CHECKPOINT.pt
03_weight_projection/A05_WEIGHT_MANIFEST.json
03_weight_projection/STRICT_LOAD_RESULT.json
```

# 7. 核心新指标：变化来源分解

以后不能只看aggregate flip。

定义：

```text
B = D1 final prediction
T = A05_LOGIT_TEACHER final prediction
C = candidate final prediction
S = {pixel | B != T}
A = {pixel | B == T}
```

## 7.1 Desired adoption

在S内：

```text
C == T
```

candidate成功采用teacher相对D1的变化。

## 7.2 Unresolved

在S内：

```text
C == B
```

candidate保留D1，尚未采用teacher。

## 7.3 Third-class change

在S内：

```text
C != T and C != B
```

candidate产生第三种类别，应尽量接近0。

## 7.4 Novel change

在A内，D1与teacher原本一致，但：

```text
C != B
```

这是teacher没有要求的变化，也是P1最可能的核心问题。

## 7.5 输出指标

新增：

```text
frozen_code/audit_teacher_projection.py
```

输出：

```json
{
  "baseline_d1_teacher_flip": 0.0,
  "candidate_teacher_flip": 0.0,
  "candidate_d1_flip": 0.0,
  "desired_adoption_pixels": 0,
  "desired_adoption_rate_on_S": 0.0,
  "unresolved_pixels": 0,
  "unresolved_rate_on_S": 0.0,
  "third_class_pixels": 0,
  "third_class_rate_on_S": 0.0,
  "novel_change_pixels": 0,
  "novel_change_rate_on_A": 0.0,
  "net_useful_ratio": 0.0
}
```

建议：

```text
net_useful_ratio = desired_adoption_pixels / max(novel_change_pixels + third_class_pixels, 1)
```

按全局、逐类、逐图分别输出。

## 7.6 A05_WEIGHT gate

A05_WEIGHT进入候选池必须满足：

1. `candidate_teacher_flip < D1_teacher_flip`；
2. `desired_adoption_pixels > novel_change_pixels`；
3. `net_useful_ratio > 1.0`；
4. third-class rate足够低，建议 `<0.05%全像素`；
5. per-image max novel change不过度；
6. class-share相对teacher任一类差值≤0.2pp；
7. canonical H300相对D1下降≥−0.5pp；
8. 任一source class IoU下降≥−2pp；
9. 单checkpoint、strict load、GPU2 exact-D4。

如果 `candidate_teacher_flip <0.2%` 且其他gate通过，A05_WEIGHT优先于任何ETKD checkpoint。

# 8. Phase 3：Functional Weight Projection（FWP）

只有A05_WEIGHT不够接近teacher时执行。

## 8.1 思路

保持candidate严格位于D1已验证参数方向的低维子空间：

```text
theta(a2,a3,ah)
 = parent
 + a2*Delta_stage2
 + a3*Delta_stage3
 + ah*Delta_head
```

固定：

```text
stage0 = parent
stage1 = parent
未变化buffers = parent
```

这是单checkpoint参数投影，不是推理ensemble。

## 8.2 冻结128张无GT投影子集

不能随便取前128张。用已冻结的 D1↔teacher 每图flip和class share构造分层子集：

- disagreement低/中/高分位均覆盖；
- 覆盖8类面积模式；
- 包含极端图像；
- 不使用GT；
- 一次冻结后不得根据结果更换。

输出：

```text
04_fwp_subset/FWP_SUBSET_128.json
04_fwp_subset/FWP_SUBSET_128.sha256
```

## 8.3 第一轮小网格

固定 `ah=0.5`，仅测试：

```text
a2 ∈ {0.35, 0.50, 0.65}
a3 ∈ {0.35, 0.50, 0.65}
```

共9个单checkpoint。

为何不扫更大：

- D1有效方向已知；
- 目标只是函数投影，不是无边界寻优；
- 防止把无GT teacher拟合成无限参数搜索。

## 8.4 排序目标

在128张子集上按以下顺序：

1. gate：third-class和novel-change不过量；
2. 最小candidate-teacher flip；
3. 最大net_useful_ratio；
4. class-share稳定；
5. 若近似相同，优先系数离0.5更近者。

只保留前2–3个进入1300张完整验证。

# 10. Phase 5：设计 D1-v2，目标是“更干净且不过冲”

只有Phase 4完成后才冻结D1-v2具体配方。不能预先盲定。

## 10.1 D1-v2的优化目标

不是“更像alpha teacher”，而是：

```text
提高可靠target signal的利用率
+ 限制无证据区域漂移
+ 保持source能力
+ 控制适配强度
```

## 10.2 首选改进轴：逐类平衡的agreement pseudo supervision

先审计原D1 hard mask逐类coverage。如果Background/Vegetation等大类主导，设计：

- 仍保留双teacher agreement；
- 仍保留高置信门；
- 对每类hard pixels设置图内上限或采样权重；
- 稀有类不通过降低置信阈值强行扩充；
- 使用class-balanced loss归一，而不是让大类像素数主导；
- 只改这一项，其他保持D1。

建议候选名：

```text
D1V2_CB_AGREEMENT
```

承重假设：D1有效，但target hard监督的类别质量/数量不均衡，导致step2000略过冲。

## 10.3 第二改进轴：未监督区域锚定

如果诊断显示D1或新训练在hard mask之外产生大量novel changes，可添加轻量anchor：

在可靠hard区域：

```text
学习hard pseudo CE
```

在其他target区域：

```text
保持接近parent或D1初始分布
```

例如：

```text
L_target = L_hard_on_selected
         + lambda_anchor * KL(init_model || student)_outside_selected
```

要求：

- init teacher cache固定；
- anchor只在hard mask之外；
- lambda_anchor单变量预注册；
- 不与class-balance同时首轮测试。

建议候选名：

```text
D1V2_OUTSIDE_ANCHOR
```

## 10.4 第三改进轴：训练scope

根据模块探针决定：

- 如果head不承重：冻结head；
- 如果stage3主要制造novel changes：测试stage2-only；
- 如果stage2/3均承重：保留原scope。

一次只测试一个scope变化。

## 10.5 训练强度轨迹

D1-v2必须保存：

```text
step250
step500
step750
step1000
step1500
step2000
```

每个checkpoint做轻量行为审计。不要只在step2000看结果。

预先定义正式候选可从轨迹选取，但选择规则必须在平台提交前冻结。例如：

1. 工程/安全gate通过；
2. hard-mask外novel changes最低；
3. target行为变化达到D1的合理量级但不过冲；
4. source guard通过；
5. 最多选两个checkpoint，第一次提交前同时冻结。

不能看到第一个平台分后再回头选任意step。

# 17. 可选后备：Delta-KD（不是当前立即执行项）

只有A05_WEIGHT/FWP不能逼近teacher，且D1-v2没有更强候选时考虑。

## 17.1 原理

定义：

```text
B = D1 logits
T = teacher logits
S = student logits
```

去除每像素共同logit平移：

```text
center(z) = z - mean_class(z)
Delta_T = center(T) - center(B)
Delta_S = center(S) - center(B)
```

在teacher与D1显著不同的区域学习：

```text
L_delta = weighted SmoothL1(Delta_S, Delta_T)
```

在teacher与D1一致区域锚定：

```text
L_anchor = KL(B || S)
```

目标：

```text
L_target = lambda_delta*L_delta(change_region)
         + lambda_anchor*L_anchor(agreement_region)
```

这样直接优化teacher相对D1的增量，并压制novel changes。

## 17.2 启动前条件

必须已有：

- 可靠teacher/D1 cache；
- desired/novel分解；
- 梯度冲突诊断；
- 全像素ETKD失败闭环；
- 单变量contract。

不得直接从本手册跳到Delta-KD。
