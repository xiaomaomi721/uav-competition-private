# MIC 推理失效与修复报告（2026-09-27）

## 结论

旧 MIC TREAT 包得到的 `6.976285` 不是有效的方法分数。它绑定的 ZIP：

```text
SHA256 16aba189b3e3e9eb25198d17a19dae06d547b34eb1b673b1c636010be281fae5
```

存在两个已经由源码和产物共同确认的推理缺陷：

1. 输入图片按字符串字典序排列，但输出按循环整数重新命名，导致 1299/1300 张预测对应错误 basename；
2. 第八个 D4 view 重复已有几何变换，而且 `undo_d4` 不是对应 inverse，约八分之一 logits 空间错位。

因此固定分类：

```text
RESULT_CLASSIFICATION = INVALID_METHOD_EVIDENCE_DUE_TO_CONFIRMED_FILENAME_IDENTITY_CORRUPTION
SECONDARY_D4_PROTOCOL_DEFECT = CONFIRMED
TRAINING_COLLAPSE = NOT_SUPPORTED
MIC_METHOD_RESULT = NOT_DETERMINED
```

## 证据

- 同名 MIC/A05 像素一致率只有 `20.8959169%`；
- 按旧脚本的字典序身份重排后，一致率升至 `94.6596399%`；
- 重排后单图一致率中位数 `96.3313103%`；
- 1267/1300 张重排后相对 A05 的一致率超过 80%；
- 这说明预测内容大体正常，灾难分数来自预测与文件名的错配，而非模型整体崩溃。

## 修复边界

- 不重训；保留 TREAT step8000 checkpoint；
- 新实现复用已得分 A05 推理协议，不局部修补旧 `_mic_infer.py`；
- 输出 basename 必须直接继承输入 basename；
- 8 个 D4 view 必须通过非方形坐标 round-trip；
- 用 A05 checkpoint 做 8 张图 byte-exact 金丝雀；
- 正式修复只允许物理 GPU2；
- 新包必须使用 `FIXED` 名称和新 SHA；
- 不自动提交平台。
