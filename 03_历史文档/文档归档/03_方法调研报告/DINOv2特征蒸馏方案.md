# DINOv2 特征蒸馏方案（B3 学生）

> 用途：蒸馏的完整实现蓝图，代码已验证可行性。
> 更新：2026-08-29

---

## 一、技术可行性（已 smoke 验证 ✅）

| 组件 | 形状 | 说明 |
|---|---|---|
| 学生 SegFormer-B3 stage3 特征 | (B, 512, 32, 32) | encoder 最深语义层 |
| 投影层 (Conv1x1) | 512→1024 | 学生特征投影到教师维度 |
| 教师 DINOv2-large 特征 | (B, 1370, 1024) → 去CLS → (B, 1024, 37, 37) | patch 14，518/14≈37 |
| 教师特征上采样 | 37×37 → 32×32 | 与学生 stage3 对齐 |
| 蒸馏损失 | cosine (1-cos_sim) | 已验证可算、梯度可回传 |

**关键设计决定**：
- 蒸馏点选在**学生 stage3（最深语义层，32×32）**，不逐 stage 蒸馏（4 个 stage 都对齐会引入过多约束，且 DINOv2 只有单尺度输出）。
- 教师输入 **resize 到 518×518**（DINOv2 原生 image_size），学生保持 1024×1024。
- 损失用 **cosine 距离**（方向对齐），不用 MSE（幅值对齐会强迫学生模仿教师幅值，cosine 更宽松，只对齐语义方向）。

---

## 二、蒸馏损失设计

```
total_loss = ce_loss(logits, targets) + λ * cosine_loss(proj(stage3), teacher_feat)
```

- `ce_loss`：原有交叉熵（不变）。
- `cosine_loss`：学生投影特征 vs 教师特征，逐 patch 归一化后算 1-cos。
- `λ`（蒸馏权重）：可调，初始 **1.0**，要扫（0.1 / 0.5 / 1.0 / 2.0）。

---

## 三、为什么这样设计（针对数据特点）

基于 `数据特点实证_图像层.md` 的硬约束：

1. **灰色团（背景/建筑/道路/车辆）颜色分不开，靠纹理/上下文** → DINOv2 提供的就是强纹理/上下文通用表示，蒸馏点对准这个短板。
2. **DINOv2 不熟航拍细粒度**（风险）→ 所以蒸馏只做**方向对齐（cosine）**，不做幅值对齐（MSE），避免强迫学生模仿教师不擅长的航拍幅值。
3. **只用 stage3 蒸馏**（最深语义层），因为灰色团的区分需要高层语义上下文，浅层（stage0/1）是低层纹理，蒸馏价值低且易过约束。

## 六、风险与预判

| 风险 | 预判 | 应对 |
|---|---|---|
| DINOv2 不熟航拍细粒度 | 可能把灰色团带偏 | cosine 只对齐方向 + λ 小步扫描 |
| 蒸馏是训练期额外约束，踩"训练期技巧全负"雷区 | 可能负 | 快测先判方向，负就放弃 |
| 显存（教师+学生同卡） | DINOv2 848M fp16 + B3 | smoke 已跑通，正式训练需测显存 |
| 教师特征上采样 37→32 有插值误差 | 轻微 | 可选教师输入 448(32×14) 让 patch 正好 32×32 |
