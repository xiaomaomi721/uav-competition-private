## GitHub 协作规则

- 每个阶段完成后形成一次边界明确的阶段提交。
- 不直接提交官方数据、标签、授权材料或数据压缩包。
- 不直接提交模型权重。
- 不提交缓存、日志、可视化样本和大型运行结果。
- 每次阶段提交必须同步更新对应阶段文档和根 README。
- 所有实验使用统一、固定的数据划分和指标实现。
- 正式代码合并前至少由另一名成员检查。
- 队长负责确认阶段是否达到验收标准。
- 提交前执行 Git 状态、忽略规则、绝对路径、敏感信息和大文件检查。
- 一次提交只描述一个阶段或一个可审查的逻辑目标，避免混入无关改动。

## 建议协作流程

1. 阶段开始前确认目标、验收标准、负责人和算力安排。
2. 在阶段文档中列出本阶段允许和禁止的工作范围。
3. 实现者在本地完成代码、最小验证和结果记录。
4. 另一名成员检查数据安全、配置、指标、文档和关键输出。
5. 队长根据验收标准确认是否形成阶段提交。
6. 提交后记录 commit、关键结论、遗留问题和下一阶段入口。
