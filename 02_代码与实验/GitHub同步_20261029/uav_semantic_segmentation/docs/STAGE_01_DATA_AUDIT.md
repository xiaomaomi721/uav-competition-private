# Stage 01：数据集审计与项目初始化

## 阶段目标

在不修改官方数据、不训练模型的前提下，建立可复现的数据审计工程，确认数据格式、数量、类别映射、完整性和主要风险，并准备适合 GitHub 阶段提交的文档与安全规则。

## 已完成工作

- 只读定位并识别官方训练集、初赛测试集、示例和类别说明。
- 全量检查 6996 张训练图像、6996 张标签和 500 张初赛测试图像。
- 检查图像尺寸、通道、dtype、取值范围、可读性和近恒定图像。
- 按原生单通道方式检查所有标签的尺寸、模式、dtype、像素 ID 和图像配对。
- 统计类别像素占比、图片级频率、主要组合、长尾、小目标候选和场景风险。
- 检查文件大小和 dHash 重复候选，没有删除或修复任何文件。
- 生成固定随机种子的本地可视化样本。
- 完成数据文档、团队流程、依赖清单、Git 忽略规则和报告路径脱敏。

## 数据检查结论

- 训练图像 6996 张、训练标签 6996 张、初赛测试图像 500 张。
- 图像全部为 1024×1024、RGB、uint8、PNG。
- 标签全部为 1024×1024、单通道 L、uint8、PNG，实际像素值为 0–8。
- 图像和标签完全对应；未发现空文件、损坏文件、尺寸异常或越界类别 ID。
- 官方类别映射已从 Label.txt 确认，0 为 Ignore，1 为 Background，2–8 为其余语义类别。
- Vehicle 有效像素占比约 0.783%，Barren 约 1.835%，像素长尾比约 36.745 倍。
- 主要风险是类别不平衡、Vehicle 小目标、场景差异和随机划分导致的潜在泄漏。
- 当前数据不需要人工清洗或自动修复。

## 验收标准

- 数据集数量、格式、类别 ID 和完整性有可复现报告。
- 检查脚本可以通过 <DATASET_ROOT> 在不同成员电脑运行。
- 报告统计与确认结论一致，且不包含本机绝对路径、用户名或无关项目路径。
- 官方数据、压缩包、模型权重、缓存和可视化样本受到 Git 忽略规则保护。
- 根 README、数据说明、团队流程和阶段文档内容完整且相互一致。
- 没有执行数据划分、模型训练、测试推理、提交、Git commit 或 push。
