# SHBR 一键条件链：队友执行手册

## 先看结论

这不是“本地涨分就提交”的脚本。它按以下顺序自动执行：

```text
冻结资产与协议
  → H300 只做门控开发
  → 冻结规则
  → R1099 只检查一次
  → test2 无GT支持域检查
  → beta=0.25 无更新梯度量级检查
  → 双 role 4-loop smoke
  → 只训练 TREAT@2000
  → source 只作崩溃检查
  → 单 checkpoint 打包与全量审计
  → READY 或 STOP
```

任一门失败都会生成 `FINAL_DECISION.json` 和 `给队友看的最终结论.md` 后停止。**STOP 时不训练后续阶段、不打包、不上传，也不要临时改阈值。**

脚本从不连接比赛平台，不读取 test2 GT，不停止任何进程。物理 GPU2/GPU3 是本项目授权卡，脚本只会在这两张卡中选择无计算进程的一张；两张都忙则停止。GPU0/GPU1 不属于本项目，绝不使用。

## 为什么是这条路线

1. **新论文方法的可吸收部分**：U²PL 提醒不要把所有低可靠 complement 当正标签；GoodSAM/region teacher 启发使用异构区域表示；category-adaptive thresholding 启发按盲类冻结不同门槛。这里是受启发的方案，不声称复现论文。
2. **加强已证实正收益**：最近唯一有配对线上因果正证据的是盲类召回 soft KL（相对 CONTROL `+0.5951pp`）。SHBR 保留它，只在原 A05 mask 外补经过 source GT 审计的异构盲类区域。
3. **参考历史成功共性**：真正增加 test-domain 信息、范围窄、剂量弱、单变量配对。没有 TCA complement、RAS、BLACK、CE/LR/bias/步数叠加。

TCA V2 和 CE020 已证明 source 本地排序可能与线上反向。因此 source GT 在本链条里只负责：验证 donor 的信息是否真的新、门控能否识别，以及排除崩溃；它不预测 test2 分数。

## 唯一命令

```bash
cd /data/uav/shbr_bundle
bash run_all.sh
```

可选：为了重试时得到可识别的新目录，只允许设置 run ID，不允许设置方法参数：

```bash
SHBR_RUN_ID=retry01 bash run_all.sh
```

输出只写入：

```text
/data/uav/shbr_20261003_<RUN_ID>/
```

已存在即拒绝覆盖。不要删除历史运行目录后原路径重跑。

## 状态解释和自动分支

| 状态 | 含义 | 队友动作 |
|---|---|---|
| `STOP_GPU_BUSY` | GPU2/3 均有计算进程 | 不抢卡、不 kill；保留报告，空置本轮 |
| `STOP_PROTOCOL` / `STOP_INTEGRITY` | 权重、数据、类序、score space、cache 或代码合约不确定 | 不训练、不提交 |
| `STOP_NO_COMPLEMENTARITY` | donor 没有足够的 H300 新信息 | 不打开参数网格 |
| `STOP_NO_DEPLOYABLE_GATE` | 冻结规则在 R1099 不成立 | 不训练 |
| `STOP_TARGET_OUT_OF_SUPPORT` | test2 的规则覆盖超出 source 支持范围 | 不训练 |
| `STOP_TREATMENT_SCALE` | 固定 beta=0.25 太弱/太强 | 不现场改 beta |
| `STOP_MISSING_CONTROL` / `STOP_REPLAY_MISMATCH` | 无法与冻结 CONTROL 形成可信配对 | 不训练或不打包 |
| `STOP_COLLAPSE` | source 仅作为灾难性崩溃检查失败 | 不打包 |
| `STOP_NO_EFFECT` / `STOP_BEHAVIOR_OUTLIER` | 包完全相同或行为超出弱干预边界 | 不提交 |
| `READY_FOR_MANUAL_PAIRED_SUBMISSION` | 所有预注册门通过 | 按最终文件给出的 SHA 人工成对提交 |

## READY 后的人工提交顺序

只有顶层 `FINAL_DECISION.json` 明确为 `READY_FOR_MANUAL_PAIRED_SUBMISSION` 才做：

1. 槽1：冻结 xlogy CONTROL，SHA 必须为 `1700504f...`；
2. 槽2：本次生成的 SHBR TREAT，SHA 以本次 manifest 为准。

两个包必须成对。当天少于两个槽时，两个都不交，留到下一可用日。脚本不会也不能代为上传。

回分后只计算：

```text
xlogy common shift = CONTROL - 71.045315
SHBR causal effect = TREAT - CONTROL
new champion gain  = TREAT - 71.045315
```

若 `TREAT-CONTROL <= 0`，关闭该固定配方，不继续扫 beta、threshold、region area 或 checkpoint。若净效应为正但未破冠军，先归档在线因果结果，再另立新方案；本链条不会自动衍生下一轮。

## 最后只带回什么

无需运行中来回问。结束后把整个 `/data/uav/shbr_20261003_<RUN_ID>/` 带回；至少包含：

- `FINAL_DECISION.json`
- `给队友看的最终结论.md`
- `00_preflight/ARTIFACT_RECEIPT.json`
- `02_gate/FROZEN_GATE.json`
- `02_gate/GATE_DECISION.json`
- `02_gate/SOURCE_COMPLEMENTARITY.json`
- 若进入后续阶段，再带回 target support、beta receipt、训练 summary/checkpoint、package manifest 和 ZIP。

无论 READY 或 STOP，都不要只截一行终端输出；完整目录才是可审计交付。
